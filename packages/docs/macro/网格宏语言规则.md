# 网格宏语言规则

> 版本：V1.11
> 适用范围：`@u1in/shushi-macro` 的人类可写公式源码、宏 AST 与 `GridScene` 编译。

## 1. 目标与边界

网格宏语言是一种受限的声明式公式语言。它让用户以 `FUNCTION(argument, ...)` 的形式描述网格结构，并编译为通用 `GridScene`。它不包含加、减、乘、除的计算规则，不输出 DOM、CSS 类名、SVG 节点或像素坐标。

```text
宏源码 → 宏 AST → 归一化网格结构 → GridScene → DOM/CSS 或 SVG 渲染器
```

运算专属的 `BORROW`、`CARRY` 等高层宏可在未来展开为本文的基础节点；它们不应进入通用渲染器。

源码按职责分为两层：**基础宏命令**负责描述稳定的网格结构与受限配置，**语法糖宏命令**负责将更易读的文字位置、边框、点和厂字弯降级为基础网格图元。实现也一一对应为 `src/basic-macros.ts` 与 `src/sugar-macros.ts`；编译器只负责编排行列、推导轨道并协调两者。

计算器不是另一套竖式渲染协议：它会先把计算过程填写为本语言的宏字符串，再调用与人工输入完全相同的解析、校验与编译入口。因而任何自动生成的竖式源码均可复制到宏试验区复刻；自动结果没有人工无法写出的专属图元。

## 2. 基本语法

所有调用均使用大写英文函数名与小括号，参数以逗号分隔：

```text
FUNCTION(argument1, argument2)
```

`GRID` 只在需要 `columns`、`showGrid`、边距等场景配置时才需要显式声明。没有场景配置时，顶层以逗号分隔的 `ROW`、`LINE` 列表会自动包裹为隐式 `GRID`：

```text
ROW(MM(5), MM(6)),
LINE,
ROW(MM(1), MM(2))
```

为减少重复书写，顶层还支持**分号行简写**：`,` 仍然分隔同一行的单元格，顶层 `;` 分隔行。编译器会把每个普通分号段自动包裹为 `ROW(...)`，再将全部行与横线包裹为隐式 `GRID(...)`。在这个上下文中，裸文字会自动补成 `MM(text)`，因此可直接写数字和运算符。单独一段 `LINE`（或 `LINE(...)`）保留为横线，不会被包成数字行；结尾分号可写可省略。以下两段源码等价：

```text
5, 6;
×, 5, 6;
LINE;
```

```text
ROW(MM(5), MM(6)),
ROW(MM(×), MM(5), MM(6)),
LINE
```

分号行简写只作用于顶层，`CELL(...)`、`ROW(...)`、`GRID(...)` 等调用内部仍必须使用逗号分隔参数。需要配置 `columns`、`align`、`showGrid` 等选项时，继续使用显式 `GRID` 或 `ROW`。

同一单元格的多个图元可使用**方括号 CELL 简写**：`[5, RB(1)]` 等价于 `CELL(MM(5), RB(1))`。方括号的**第一项必须是 `MM(text)`，或可省略 `MM` 的裸文字**；只有这一项会自动补成 `MM`。后续项必须是完整宏调用或零参数宏，所以 `RB(1)` 不能写成 `RB`，`[5, 1]` 也无效。它可以出现在任何原本允许 `CELL(...)` 的位置，并继续支持 `KV(columnSpan, n)`、`KV(style, token)` 等单元格配置；方括号内部同样以逗号分隔。方括号是保留语法，如需把 `[` 或 `]` 作为普通文字，必须用双引号包裹。

已声明为零参数的宏可省略空括号：`LN`（`LINE`）、`EP`（`EMPTY`）、`BK`（`BRACKET`）与 `TBD`、`RBD`、`BBD`、`LBD` 分别等价于其带空括号的写法；空 `STYLE` 也遵循此规则。`LN`、`EP`、`BK` 是输入别名，解析后始终还原为完整宏名；格式化与去格式化会输出别名。需要参数的宏仍必须保留括号，例如 `MM(9)`。

简单文字、数字和保留常量可以不加引号；包含逗号、圆括号或引号时必须用双引号包裹。反斜杠可转义引号或反斜杠。

配置统一使用：

```text
KV(key, value)
```

## 3. 基础宏命令：结构与推导

```text
GRID(...children)
ROW(...cells)
CELL(...elements, ...cellOptions)
EMPTY(...cellOptions)
LINE(STYLE(...), ...lineOptions)
DIV
VALUE(number)
STYLE(...styleOptions)
```

- `GRID` 接收任意数量的 `ROW`、`LINE` 与 `KV`；省略 `KV(columns, n)` 时，编译器使用所有 `ROW` 中最大单元格跨度作为列数。默认视觉参数与首页运算器一致：`unitWidth=30`、`unitHeight=46`、`fontSizeRatio=1`、`paddingX=20`、`paddingY=12`。`KV(fontSizeRatio, n)` 以格宽乘比例计算字号；兼容绝对字号 `KV(fontSize, n)`，且绝对值优先。`KV(padding, n)` 同时覆盖四边，或可分别使用 `paddingX` / `paddingY`。
- `KV(trackUnit, half)` 启用**半格轨道模式**：所有真实列轨道均为 `0.5u`，但普通 `CELL`、`EMPTY` 与直接置于 `ROW` 的定位文本宏默认跨越两个轨道，仍显示为一个完整的 `1u` 数字格。默认 `trackUnit` 为 `full`，完全保持既有一宏一整格行为；`columnSpan` 始终按真实轨道数计数。含 `DIV` 的 `GRID` 会自动切换到该模式，无需显式声明；即使写了 `KV(trackUnit, full)` 也会被 `DIV` 覆盖。
- `KV(showGrid, true)` 可显示辅助网格，默认 `false`；兼容旧写法 `showGuideGrid`，但新的宏源码应使用 `showGrid`。
- `autoColor` 默认开启，最多支持 40 条 `ROW`（借位提示行也计入）。它使用一组面向小学课堂屏幕阅读的高饱和、中明度固定色板：正文行在 10 个色相家族间大幅跳选（红、橙、粉、品红、紫、蓝、天蓝、青、青绿、绿），并让奇偶行相差约 0.06 的明度，相邻行不会混色；色板刻意避开黄褐、橄榄、咖色与深紫，避免在中低明度下显得沉闷。进位、借位各自使用独立派生的 40 色，既不与正文复用，又保留所在行的色相关系。正文色对白底的大字号对比度不低于 3.1；当前目标为屏幕与投影教学，若需严格印刷应再整体压暗。仅在需要黑色基线时写 `KV(autoColor, false)`。自动主题定义独立放在 `src/auto-color-theme.ts`，后续替换配色不需要改动编译器。
- `ROW` 默认右对齐。`KV(align, left)` 可改为左对齐；显式 `EMPTY()` 占列，`KV(columnSpan, n)` 可扩展单元格跨度。
- `CELL` 是同格图元的唯一组合边界。`ROW(MM(5), MM(6))` 会归一化为两个独立的 `CELL`；若 `9` 与借位点要叠在一格，可写成 `CELL(MM(9), MTD)` 或简写 `[9, MTD]`。
- 连续 `ROW` 间具有隐式、无样式的逻辑分隔边界；它不产生可见轨道或横线。
- `LINE` 始终附着到上一条数字行的下边，不产生额外行高。未传参的 `LINE` 默认使用渲染器黑色和 `2px` 样式及 `span=previous`，即只覆盖上一行有效范围，不强制与其他横线等宽；`longest` 取所有数字行的最小包围范围；`full` 覆盖整个已解析列宽。

显式配置优先级为：**显式配置 > 自动推导 > 默认值**。显式 `columns` 小于最长行所需列数会报错，不会截断内容。

### 3.1 短除法分割线：`DIV` 与 `VALUE`

`DIV` 是结构宏。只要 `GRID` 的任意 `ROW` 直接包含 `DIV`，编译器就自动把整个 `GRID` 提升为短除法半格模式，无需再写 `KV(trackUnit, half)`。它不占用列、不代表一个文字单元格，而是把所在 `ROW` 分为左侧的一个除数单元格和右侧的一个或多个 `VALUE` 数值组。可省略参数；需要主题 token 时可写 `DIV(KV(separatorStyle, token), KV(barStyle, token))`：

```text
GRID(
  ROW(MM(2), DIV, VALUE(60)),
  ROW(MM(2), DIV, VALUE(30)),
  ROW(MM(3), DIV, VALUE(15)),
  ROW(VALUE(5))
)
```

也可以直接用顶层分号简写；编译器会自动补齐 `ROW` 与隐式 `GRID`，并因 `DIV` 自动进入半格模式：

```text
2,DIV,VALUE(60);2,DIV,VALUE(30);3,DIV,VALUE(15);VALUE(5);
```

- 含 `DIV` 的 `GRID` 只能包含 `ROW` 与 `KV`；`DIV` 必须是 `ROW` 的直接子项，不能嵌套在 `CELL` 中。它不接受文字或 `STYLE`，只接受可选的 `separatorStyle` 与 `barStyle` token。
- `VALUE(number, KV(style, token))` 是右侧或底行的数值组。它会逐位展开为完整数字格；因此 `VALUE(60)` 与 `VALUE(84)` 是两个可独立右对齐的组，而不是四个没有边界的文字单元格。它只允许可选的 `KV(style, token)`，以便自动竖式与人工源码共用语义主题。`VALUE("")` 表示不绘制文字的占位数值组，常用于带额外余数列的末行；仍会保留该组的对齐边界。
- 含 `DIV` 的过程行左侧必须恰有一个普通单元格，右侧至少有一个 `VALUE`；整个短除法的最后一行必须不含 `DIV`，且只由数量一致的 `VALUE` 组组成。
- 编译器读取所有过程行后，按每个 `VALUE` 组的最大位数固定右边界，并从下向上自动在较上方的分割线左侧补 `0.5u` 阶梯。`DIV` 最终输出右侧首组真实左边界上的竖线，以及从该边界到数值区右端的本行横线。
- 多输入公因数短除法只需在 `DIV` 右侧写多个 `VALUE`；相邻数值组会自动保留一个半格空隙：

```text
GRID(
  ROW(MM(2), DIV, VALUE(60), VALUE(84)),
  ROW(MM(2), DIV, VALUE(30), VALUE(42)),
  ROW(MM(3), DIV, VALUE(15), VALUE(21)),
  ROW(VALUE(5), VALUE(7))
)
```

`DIV` 只负责结构和版式，既不选择质因数，也不计算 GCD / LCM；这些仍属于计算层。辅助网格会显示每一条真实半格轨道，用于检查自动补齐结果；普通渲染没有单元格边框，跨两轨道的数字视觉上仍是一格。

## 4. 语法糖宏命令：单元格图元

九宫格文本宏均接收一个文字参数，可追加 `KV(style, token)` 或 `KV(fontSizeRatio, number)`：

```text
LT(text) MT(text) RT(text)
ML(text) MM(text) MR(text)
LB(text) MB(text) RB(text)
```

`MM` 与 `DOT` 保持题目数字的正常字号；`DOT` 仍附着于左侧单元格的右边界。其余非单元格中心的文本锚点（包括 `RBL`）未显式设置 `fontSizeRatio` 时，默认采用 `0.42`，与现有加法、乘法进位教学标记一致；此默认值只调整字体大小，不改写文字颜色或样式 token。需要常规大小时可显式写 `KV(fontSizeRatio, 1)`。

`MTD` 是 `MT(·)` 的零参数简写，固定使用中上锚点、`0.42` 教学字号和借位色，专用于减法借位点。它可写成 `MTD` 或 `MTD()`，在方括号 CELL 简写中作为后续项写作 `[5, MTD]`；不接受文字参数，需要其他借位文字时仍使用 `MT(text)`。

加法等需要进位时，用 `RB(text)` 与该位数字共同放进 `CELL`；`RB` 默认使用教学标记字号，位于数字右下角：

```text
ROW(MM(3), MM(5), MM(6)),
ROW(MM(+), CELL(MM(2), RB(1)), CELL(MM(7), RB(1)), MM(8)),
LINE,
ROW(MM(6), MM(3), MM(4))
```

自动配色开启时，`RB` 约定为进位标记、`MT` 约定为借位标记；二者均按所在行取得独立色，且不会与普通数字行共用颜色。普通文本行按每十行为一组的蓝青、青绿、橄榄金、暖玫红紫主题渐变；各组边界使用相邻色衔接，既能区分相邻行，也避免长竖式出现突兀跳色。运算符根据 `+`、`−`/`-`、`×`/`*`、`÷`/`/` 取得各自的全局独占色。`DOT` 始终取得小数点独占色，即使其 `CELL` 或宏带有样式 token 也不会被覆盖。

`RBL(text)` 位于当前单元格右边界的文字行框位置，用于附属小数点。`DOT` 是 `RBL(.)` 的简写，通常与左侧数字置于同一个 `CELL`：

```text
CELL(MM(7), DOT)
```

当前 `GridScene` 使用既有的右侧 `edgeMidpoint` 与普通文本一致的行框对齐实现 `RBL`，因此 DOM/CSS 与 SVG 均以同一文本排版策略显示它；它不会修改列轨道或行高。

`BRACKET` 是完整厂字宏：它编译为通用 `corner(bottomRight)` 图元，并自动从自身右上角沿当前行的上边界延伸到网格最右边界，生成厂字横。所在真实列的轨道尺寸变为 `0.5u`，与现有除法厂字弯列一致；因此被除数各格不需要重复写 `TBD`。它必须独占一个单元格，可简写为：

```text
ROW(MM(3), BK, MM(1), MM(4))
```

或写成 `CELL(BK)`；不可与数字、边框或其他定位图元组合，也不可设置 `columnSpan`。若其右侧没有列，只保留厂字弯而不生成零长度厂字横。

单元格边框宏只能置于 `CELL` 内，分别对应完整单元格区域的上、右、下、左边：

```text
TBD(STYLE(...))
RBD(STYLE(...))
BBD(STYLE(...))
LBD(STYLE(...))
```

它们同样可追加 `KV(style, token)`，但不接收文字。与 `LINE()` 一样，空参数的边框宏默认使用黑色、`2px` 样式；例如：

```text
CELL(MM(8), BBD())
```

## 5. 线条样式

线条样式是跨渲染器的受限声明，不是任意浏览器 CSS：

```text
LINE(
  STYLE(KV(color, "#6d83ae"), KV(thickness, 2)),
  KV(span, previous)
)
```

省略样式时可直接写 `LINE`，它会使用默认横线样式。要显示辅助格线，则在 `GRID` 中加入 `KV(showGrid, true)`。

自动配色默认开启时，`LINE` 与 `TBD/RBD/BBD/LBD` 使用主题的 `rule.color` 与 `rule.thickness`；`BRACKET` 生成的厂字弯和厂字横则共同使用独立的 `bracketRule.color` 与 `bracketRule.thickness`。这时 `STYLE` 中的线色和线宽仅保留在源码，不参与最终自动配色输出。写 `KV(autoColor, false)` 后才使用黑色基线或显式 `STYLE`。

`STYLE` 当前支持：

- `color`：DOM/SVG 共同支持的颜色值；
- `thickness`：正数像素线宽。

此外，`LINE` 可通过 `KV(style, token)` 使用已有语义样式 token。宏编译器把上述受限样式降级为 `GridLineContent.color` 和 `GridLineContent.thickness`，由两类渲染器共同消费。

## 6. 完整示例

```text
5, [6, RB(1)];
LN;
[7, DOT];
```

此例自动推导为两列：首行显示 `56`，横线位于其下边，第二行中的 `7.` 右对齐到末列。

## 7. 验证

宏包的行为由 Web 工作区测试覆盖。修改语法、归一化或 `GridScene` 输出后，必须执行：

```bash
source ~/.zshrc
npm run typecheck
npm run test
npm run build
```

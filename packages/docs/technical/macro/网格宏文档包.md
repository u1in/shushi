# 网格宏文档实现说明

> 适用范围：`packages/docs-site/` 内的宏文档 Vue 展示组件、图例、样式与 VuePress 接入方式；宏文档内容源位于 `@u1in/shushi-docs/src/macro`。

## 1. 包职责

宏文档展示组件已经并入 `packages/docs-site/`，不再作为独立 workspace 包。它负责：

- 文档块渲染与交互状态；
- 可运行示例、完整版/语法糖版对照与结果预览；
- 九宫格、方位/边框、RBD baseline、厂字弯等图例；
- 文档专用 SVG 预览与样式。

`@u1in/shushi-docs` 是宏文档内容、分组和导航顺序的唯一来源，图例数据也由其 `gallery/` 子模块集中维护。计算器自动生成的竖式宏源码与人工宏共享相同的解析、编译和文档契约；其中首页“复制宏命令”统一通过 `minifyMacroForCopy` / `minifyMacroForCopyAst` 导出最简源码，不由页面或布局器自行序列化、裁剪别名或删除页面专属参数。右对齐行首只用于缩进的 `EMPTY` 会在压缩时省略，尾部占位格仍保留；横线压缩同样在该统一链路执行：单条全宽横线省略行级 `span`，多条同跨度横线提升为 `GRID(lineSpan)`。`@u1in/shushi-web` 只负责首页演示，包括 AST 元素检查器通过 `createMacroAstInspection` 展示的“渲染元素 → AST 节点 → 按输入风格回写宏源码”交互链路，以及通过 `removeElementStrike` 删除 `STRIKE`、将 `STRIKEDOT` 回退为 `DOT` 的操作，不再挂载宏文档路由或维护文档页面。VuePress 则由 `@u1in/shushi-docs-site` 负责发布。

API 文档只保留公共 API 查阅内容，按使用门槛分为`常用 API`与`高级 API`。常用 API 从门户调用、宏源码处理、AST 交互和直接渲染开始；高级 API 收纳 AST 底层编译/序列化、计算器与布局器内部接口、几何和播放辅助函数，并按预估使用频率从高到低排列。每个 API 独立成页，并按“名称 → 例子 → 作用 → 函数签名和属性说明 → 注意事项”组织。宏语言参考保留前言、基础语法、基础宏命令、别名宏、方位宏、符号与边框、语法糖与实践排错。`MTD`、`DOT`、`SQ`、`TRI`、`RND` 统一归入“别名宏”分组；`STRIKE` 与 `STRIKEDOT` 归入“符号与边框”分组，并分别发布为独立文档：`STRIKE` 描述数字删除线，`STRIKEDOT` 描述带删除线的小数点。它们分别提供借位点、小数点、固定符号和等值变换标记等能力。

## 2. 目录结构

```text
packages/docs-site/
├── src/
│   ├── macro-docs-components/ # 文档渲染组件与图例
│   └── macro-docs-styles/     # 文档样式
└── test/macro-docs.test.ts    # 宏文档契约与示例测试

packages/docs/src/macro/   # 宏文档内容、类型、分组与导航（唯一来源）
```

## 3. 内容模型

内容页面定义在 `packages/docs/src/macro/`，每个页面是一个 `MacroDocPage`：

- `slug`：页面标识；宏语言参考页面最终为 `/macro-rules/<slug>`，API 文档页面最终为 `/macro-api/<slug>`；
- `group`：所属导航分组；
- `sections`：页面章节，每节有唯一 `id` 与一组 `DocBlock`；
- `apiTier`：API 页面所属的使用层级，取 `common` 或 `advanced`，决定可见二级菜单和页面顺序；
- `summary`：页面摘要；
- `kicker`、`navLabel`：显示在页面头部和侧边栏的短标签。

`DocBlock` 支持段落、列表、表格、代码块、可运行示例、对照、提示框、步骤、卡片和各类图例。新增展示类型时，先扩展 `packages/docs/src/macro/types.ts`，再在 `packages/docs-site/src/macro-docs-components/MacroDocBlocks.vue` 中实现渲染。

## 4. 新增或修改页面

1. 在 `packages/docs/src/macro/` 中修改对应分组文件，或新建一个页面文件；
2. 在 `packages/docs/src/macro/index.ts` 的 `pagesByGroup` 中登记该页面；
3. 新分组需要同时修改 `DocGroupId` 与 `macroDocGroups`；
4. API 内容源通过 `macroDocApiNavGroups` 维护“常用 API / 高级 API”和页面顺序，VuePress 侧栏按同一顺序做发布适配，生成“API 文档 → 常用 API / 高级 API → API 名称”目录；普通侧栏、页内目录、上一页/下一页和路由仍从同一份页面清单生成；
5. 示例与对照代码必须可编译，并补充到 `packages/docs-site/test/macro-docs.test.ts` 的检查范围。

## 5. UI 组件

- `MacroDocBlocks.vue`：把 `DocBlock` 分派到具体展示组件；
- `MacroExampleCard.vue`：源码 + SVG 预览；
- `MacroCompare.vue`：完整版、语法糖版和结果预览按三行纵向对照，并显示等价标记；
- `MacroGridPreview.vue`：文档站自带的轻量 SVG 预览，不依赖 `packages/web` 的 `GridPreview`；
- `DocText.vue`：反引号行内代码与粗体文本。

## 6. 样式

文档展示样式集中在 `packages/docs-site/src/macro-docs-styles/macro-docs.css`。对照组件固定使用三行纵向布局，让源码区域和结果预览获得完整宽度；组件内部标题必须重置宿主文档样式的 `padding-top`，VuePress 站点同时只给基础文档标题保留锚点偏移；VuePress 客户端直接引入：

```ts
import './src/macro-docs-styles/macro-docs.css'
```

样式只负责文档外壳与文档专用图例/预览；首页演示的 Tailwind 基础主题由 `packages/web/src/styles/main.css` 独立提供。

## 7. VuePress 接入

VuePress 站点从 `@u1in/shushi-docs/macro` 读取内容，并从本地宏文档组件目录注册 `MacroDocCatalog`：

```ts
import MacroDocBlocks from './src/macro-docs-components/MacroDocBlocks.vue'
```

`MacroDocCatalog` 负责把宏语言参考和 API 文档接入 VuePress 页面；页面数据仍由 `@u1in/shushi-docs/macro` 自动生成，不需要在 web 包登记路由。`packages/web` 只保留首页演示。

## 8. 验证

从仓库根目录执行：

```bash
source ~/.zshrc
npm install
npm run typecheck
npm run test
npm run build
```

宏文档测试现在由 `npm run test:docs-site` 执行；文档站整体使用 `npm run docs:build` 验证。

新增依赖后，已有的 Vite 开发服务器需要重启，才能重新解析新的 workspace 包。

# 网格宏文档包

> 适用范围：`@u1in/shushi-macro-docs` 的 Vue 展示组件、图例、样式与主应用接入方式；宏文档内容源位于 `@u1in/shushi-docs/src/macro`。

## 1. 包职责

`@u1in/shushi-macro-docs` 是网格宏语言的运行时展示组件包。它负责：

- 文档块渲染组件与交互状态；
- 文档页面布局、页内目录、上一页/下一页；
- 可运行示例、完整版/语法糖版对照与结果预览；
- 九宫格、方位/边框、RBD baseline、厂字弯等图例；
- 文档专用 SVG 预览与样式。

`@u1in/shushi-docs` 是宏文档内容、分组和导航顺序的唯一来源，图例数据也由其 `gallery/` 子模块集中维护。计算器自动生成的竖式宏源码与人工宏共享相同的解析、编译和文档契约。`@u1in/shushi-web` 只负责挂载 `/macro-rules`（宏语言参考）与 `/macro-api`（技术文档）两个兼容入口、提供主应用外壳和全局 Tailwind 主题；首页的 AST 元素检查器通过 `createMacroAstInspection` 展示“渲染元素 → AST 节点 → 最简宏源码”的交互链路。VuePress 则由 `@u1in/shushi-docs-site` 负责发布。

技术文档按板块拆分：`入门` 包含安装与快速使用，`API` 目录直接平铺并直接链接到所有面向用户的公共 API 页面；宏编译、渲染、网格和文本、布局、计算分类只保留为内容元数据分组，不渲染为二级目录。每个 API 独立成页，并按“名称 → 例子 → 作用 → 函数签名和属性说明 → 注意事项”组织。宏语言参考保留前言、基础语法、各宏命令、语法糖与实践排错。

## 2. 目录结构

```text
packages/macro-docs/
├── src/
│   ├── components/       # 文档渲染组件与图例
│   ├── pages/            # 文档外壳页与单篇文档页
│   ├── styles/           # 文档样式
│   └── index.ts          # 包的公共入口
└── package.json

packages/docs/src/macro/   # 宏文档内容、类型、分组与导航（唯一来源）
```

## 3. 内容模型

内容页面定义在 `packages/docs/src/macro/`，每个页面是一个 `MacroDocPage`：

- `slug`：页面标识；宏语言参考页面最终为 `/macro-rules/<slug>`，技术文档页面最终为 `/macro-api/<slug>`；
- `group`：所属导航分组；
- `sections`：页面章节，每节有唯一 `id` 与一组 `DocBlock`；
- `apiArea`：API 页面所属的内部分类，取 `compile`、`render` 或 `grid`，不生成可见二级菜单；
- `summary`：页面摘要；
- `kicker`、`navLabel`：显示在页面头部和侧边栏的短标签。

`DocBlock` 支持段落、列表、表格、代码块、可运行示例、对照、提示框、步骤、卡片和各类图例。新增展示类型时，先扩展 `packages/docs/src/macro/types.ts`，再在 `packages/macro-docs/src/components/MacroDocBlocks.vue` 中实现渲染。

## 4. 新增或修改页面

1. 在 `packages/docs/src/macro/` 中修改对应分组文件，或新建一个页面文件；
2. 在 `packages/docs/src/macro/index.ts` 的 `pagesByGroup` 中登记该页面；
3. 新分组需要同时修改 `DocGroupId` 与 `macroDocGroups`；
4. API 侧栏直接读取 `api` 分组页面清单，生成“API → API 名称”目录；`macroDocApiNavGroups` 仅供内容分类和测试使用，不生成可见的二级目录；普通侧栏、页内目录、上一页/下一页和路由仍从同一份页面清单生成；
5. 示例与对照代码必须可编译，并补充到 `packages/web/test/macro-docs.test.ts` 的检查范围。

## 5. UI 组件

- `MacroDocsLayout.vue`：顶栏、侧边栏、移动端抽屉、`RouterView`；
- `MacroDocPage.vue`：页面头部、章节、页内目录、翻页；
- `MacroDocBlocks.vue`：把 `DocBlock` 分派到具体展示组件；
- `MacroExampleCard.vue`：源码 + SVG 预览；
- `MacroCompare.vue`：完整版、语法糖版和结果预览按三行纵向对照，并显示等价标记；
- `MacroGridPreview.vue`：文档包自带的轻量 SVG 预览，不依赖 `packages/web` 的 `GridPreview`；
- `DocText.vue`：反引号行内代码与粗体文本。

## 6. 样式

文档展示样式集中在 `src/styles/macro-docs.css`，通过包的 `style.css` 导出。对照组件固定使用三行纵向布局，让源码区域和结果预览获得完整宽度；组件内部标题必须重置宿主文档样式的 `padding-top`，VuePress 站点同时只给基础文档标题保留锚点偏移；主应用和 VuePress 站点均可引入：

```css
@import "@u1in/shushi-macro-docs/style.css";
```

样式只负责文档外壳与文档专用图例/预览；主应用的 Tailwind 基础主题仍由 `packages/web/src/styles/main.css` 提供。

## 7. 主应用接入

`packages/web/src/main.ts` 从包入口读取内容清单与页面组件；VuePress 站点从 `@u1in/shushi-docs/macro` 读取内容，并注册 `MacroDocCatalog`：

```ts
import { MacroDocPage, MacroDocsLayout, macroDocPages } from '@u1in/shushi-macro-docs'
```

两个入口分别使用 `MacroLanguageDocsPage` 与 `MacroApiDocsPage`，它们各自包装 `MacroDocsLayout` 并固定 `area`：`/macro-rules` 只显示宏语言参考分组，`/macro-api` 只显示技术文档分组。具体页面仍由 `macroDocPages` 自动生成，不需要在 web 包逐个登记。

## 8. 验证

在 WSL 中加载 fnm 环境后，从仓库根目录执行：

```bash
source ~/.zshrc
npm install
npm run typecheck
npm run test
npm run build
```

新增依赖后，已有的 Vite 开发服务器需要重启，才能重新解析新的 workspace 包。

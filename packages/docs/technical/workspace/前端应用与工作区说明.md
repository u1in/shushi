# @u1in/shushi：多包工作区说明

> 适用范围：`@u1in/shushi-*` npm workspaces 的组织、依赖边界与本地开发

## 1. 包清单

| 包名 | 责任 | 公共 API |
| --- | --- | --- |
| `@u1in/shushi-core` | 面向 npm 使用者的统一入口，汇总运行时领域包、竖式门户和渲染器公共 CSS | `shushi`、`compute*`、`create*MacroSource`、`compileMacro`、`renderDomGrid`、`renderSvgGrid`、`renderSvgString`、`style.css` 以及网格工具 |
| `@u1in/shushi-grid` | 通用行列网格类型与轨道几何 | `GridScene`、`GridElement`、`resolveGridMetrics` 等 |
| `@u1in/shushi-calculators` | 加、减、乘、除、短除法和按书写顺序组合的纯计算过程 | `computeAddition`、`computeSubtraction`、`computeDivision`、`computeMultiplication`、`computeShortDivision`、`computeCompositeArithmetic` 及计算结果类型 |
| `@u1in/shushi-layout` | 根据运算结果决定竖式结构并生成网格 | 五种 `create*GridScene` 函数及布局设置类型 |
| `@u1in/shushi-renderers` | 把网格渲染为 DOM/CSS、SVG 或 SVG 字符串 | `renderDomGrid`、`renderSvgGrid`、`renderSvgString` |
| `@u1in/shushi-docs` | 框架无关的集中式宏说明、技术文档与图例源 | `macroDocPages`、规则 Markdown |
| `@u1in/shushi-docs-site` | VuePress 发布适配层 | `docs:dev`、`docs:build` |
| `@u1in/shushi-macro-docs` | 网格宏文档的 Vue 页面组件、图例与样式 | `MacroDocsLayout`、`MacroDocPage`、`MacroDocBlocks` 等 |
| `@u1in/shushi-web` | 首页演示、计算器交互、Tailwind 主题和 Vite 前端应用 | 首页演示入口，不作为其他领域包的依赖 |

根工作区包名为 `@u1in/shushi`，应用与文档包保持私有；`@u1in/shushi-core` 是面向 npm 发布的统一入口。它在构建时把运行时领域包汇总为单一 ESM 文件、单一类型声明入口和 `style.css` 样式入口。普通数值调用优先使用 `shushi`：它委托计算器、布局器和宏编译器，并返回三层产物，不形成新的规则或渲染分支。浏览器调用 `renderDomGrid` 或 `renderSvgGrid` 时应额外导入 `@u1in/shushi-core/style.css`；纯计算、宏编译和 `renderSvgString` 不需要浏览器 DOM。源码中的各领域导入统一使用 `@u1in/shushi-*` 命名，`@u1in/shushi` 仅作为工作区根包名。

## 2. 依赖与数据流

```text
@u1in/shushi-calculators ──计算过程──┐
                                             ↓
@u1in/shushi-grid ←──── @u1in/shushi-layout
          ↑                                      ↓ GridScene
          └──── @u1in/shushi-renderers ──┘
                         ↑
                 @u1in/shushi-web
```

- `calculators` 与 `grid` 是底层纯 TypeScript 包，不能导入浏览器 API。
- `layout` 只根据计算结果和布局设置构建 `GridScene`，不创建 DOM 或 SVG。
- `renderers` 只读取 `GridScene`，不含除法、乘法、进位或借位等规则；SVG 字符串与 SVG DOM 输出共享无 DOM 渲染树，分别负责序列化和浏览器节点物化。
- `web` 负责首页演示的 Vue 状态、计算器交互和页面组件；`packages/web/index.html` 是唯一 Vite 应用壳，应用只挂载首页，不维护独立文档路由。
- `docs` 保存框架无关的文档正文、宏内容清单和图例数据；`macro-docs` 依赖 `docs`、`macro`、`grid` 与 `renderers`，提供宏文档 Vue 展示组件与文档专用 SVG 预览；`docs-site` 负责 VuePress 发布；`web` 只负责首页演示，不再维护文档入口、命名图谱或图例说明正文。
- `docs/agent/` 保留 Agent 公共指南的 Markdown 原文，由部署流程复制为站点根目录的独立 `.md` 文件；VuePress 不扫描这些文件、不生成对应的 HTML 页面，也不加入顶部导航或侧边栏栏目。

## 3. 新增代码的位置

- 新运算算法和结果类型：`packages/calculators/src/`；同时更新对应的中文计算规则文档。
- 新运算的布局引擎与布局设置：`packages/layout/src/`；同时更新对应的中文竖式排版规则文档。
- 共享网格契约或轨道几何：`packages/grid/src/`；同时更新 [`网格架构.md`](../grid/网格架构.md)。
- 通用 SVG / SVG 字符串 / DOM/CSS 绘制能力：`packages/renderers/src/`；同时检查各渲染入口和通用架构文档。
- 首页演示交互或主题：`packages/web/src/`；保持单一首页入口，不新增文档路由或 HTML 入口。文档正文、宏说明和图例数据应写入 `packages/docs/`，由 VuePress 展示。
- 网格宏文档内容：`packages/docs/src/macro/`；说明图例或文档交互：`packages/macro-docs/src/`；修改后运行 `npm run test:macro-docs` 与 `npm run docs:build`，不再检查 web 包中的文档路由。

首页宏试验区（`MacroPlayground`）的工具栏将 `源码形式` 与 `格式化` 并排展示：前者提供“最简形式”和“完整形式”，后者提供“格式化”和“去格式化”。具体宏命令请参阅宏语言文档；下方加、减、乘、长除与短除法示例不维护硬编码宏源码，统一走“计算器 → 布局器 → `minifyMacroForCopy`”生成，再在载入时格式化；测试会校验各形式与对应计算器链路都能编译为一致场景。

文档站首页 Hero 右侧的竖式 demo（`DocsHomeExperience`）额外提供一个最简宏源码单行输入框，默认值为 `3,5,6;+,[2,RB(1)],[7,RB(1)],8;LN;6,3,4;`。demo 不维护另一份场景或计算结果，始终把输入框当前内容交给 `compileMacro` 并替换 DOM 竖式；宏暂时不合法时保留上一次可渲染结果并显示错误提示。demo 使用固定高度和自适应宽度的滚动容器，竖式会按可用宽度等比缩放到不产生横向滚动条，顶部保留安全间距；过长内容只在容器内纵向溢出，用户可通过滚动条查看，不会撑大 Hero 网格区域。

首页 AST 检查器的左侧面板默认使用最简宏源码示例，允许直接输入宏源码并在每次输入时尝试编译；编译失败时保留上一次可渲染结果并显示错误。示例按钮与宏试验区共用由计算器、布局器和复制导出 API 生成的六组运算示例，载入后格式化源码并重新建立 AST 检查结果。点击右侧 SVG 图元后，结果区标题下方、渲染区域之前横向展示渲染元素、AST 节点、AST 路径和局部修改输入，输入文字后 AST 会按“宏源码”输入框当前的完整版或最简版风格直接回写源码。该输入框使用独立的主题变量：浅色模式显示浅底深字，深色模式显示深底亮字；主题控件位于首页吸顶 Header 中，仅保留浅色 / 深色按钮，由按钮自身的标签和选中状态承担主题说明。独立 Web 演示首次进入时读取系统 `prefers-color-scheme` 选择浅色或深色按钮，用户手动选择后保存显式主题，并以 `html[data-theme]` 为准。

首页 Header 同时提供宏试验区、AST 检查器、五种运算和组合竖式的锚点导航；各板块使用稳定的 `id` 和 `scroll-margin-top`，点击导航后滚动到吸顶 Header 下方的对应工作区。

首页的控制区、结果卡和 OCR 弹窗在浅色与深色主题下都保留背景、边框和阴影层次；设置控件内部的 `.settings-panel` 作为面板内容区域保持透明，避免截图中的控件区域形成额外边界。

`GridPreview` 是首页计算器共享的画板宿主。它在 `division-stage` 相对定位容器内同时挂载 SVG 与 DOM/CSS 网格：舞台占满各自父容器，宿主通过 `ResizeObserver` 在可用宽度不足时等比缩小固定坐标的 `GridScene`，不会在宽容器中放大原始字号，从而避免双渲染面板产生横向滚动，同时保证绝对定位图元使用同一组场景尺寸。SVG 节点保留 `division-svg` 样式类以复用语义 token 的字体、颜色和线条主题。SSR 使用 `renderSvgString` 时不经过这个宿主，但仍消费同一份无 DOM SVG 渲染树；修改渲染结构时，必须同时检查浏览器 SVG、DOM/CSS 和 SSR 字符串输出。

每个首页计算器都通过 `StepPlaybackControls` 独立检查自己的过程；“开始 / 上一步 / 下一步”改变布局设置中的 `visibleStepCount`，“结束”恢复未设置游标的完整场景。控制器不重算、不修改计算器过程 JSON，只请求布局层重新生成当前步骤的 `GridScene`。

组合竖式演示使用 `computeCompositeArithmetic` 逐项委托已有加、减、乘计算器；布局层将各步骤的 `ROW` 与 `LINE` 连续编排为一份可编辑宏源码和一个 `GridScene`，并按全局 `visibleStepCount` 映射局部播放帧。组合乘法关闭十倍数快捷计算并保留表达式操作数顺序，渲染器不增加组合运算分支。右侧结果标题行使用 `VisibleTextRowsPanel`，用户点击 OCR 按钮后才调用 `extractVisibleTextRows(scene)` 并在弹窗中查看当前单一场景的按行结果。

五种运算工作区的第一列控制面板统一提供英文 kicker、中文标题和一句副标题，再放置输入与设置控件；副标题说明该运算的教学过程，不承担计算逻辑。

所有首页计算器的结果标题行都提供“复制宏命令”按钮。按钮统一调用宏包的 `minifyMacroForCopy` API：保留当前输入、设置和可见步骤对应的可见网格配置，移除网页专属的 `ariaLabel` 与 `style` KV，并由 API 生成最简宏源码；复制写入统一优先使用 Clipboard API，不可用时使用浏览器原生复制回退。

乘法首页的两个输入框按用户输入顺序标为“第一个乘数 / 第二个乘数”；计算层内部仍可根据竖式规范化，把它们映射为 `multiplicandDigits` 与 `multiplierDigits` 两种行角色。

首页每个运算板块采用控制区、结果区和核心实现代码区三列布局；宽屏第三列固定为 600px，代码面板采用窄编辑器风格，示例源码通过手动分行保持可读性，不依赖自动折行。中等宽度时面板落到下一行，窄屏自动变为单列。有“复制宏命令”的计算器将 `VisibleTextRowsPanel` 的空心 OCR 按钮放在复制按钮右侧，宏试验区和 AST 检查器则直接放在结果标题行右侧。页面初始不展示 OCR 内容，点击按钮时才调用 `extractVisibleTextRows(scene)` 并打开弹窗呈现 JSON。第三列代码面板展示当前板块的 TypeScript 核心调用链，提供语法高亮和“复制全部代码”按钮。

竖式命名图谱和宏语言说明统一由 VuePress 文档站展示；`packages/web` 不再包含命名图谱页面、文档路由或文档样式。

## 4. 开发与验证

在 WSL 中先加载 fnm 环境，然后从仓库根目录运行：

```bash
source ~/.zshrc
npm install
npm run typecheck
npm run test
npm run build
```

根目录的 `dev` 服务于 `packages/web` 首页演示；`test` 会依次运行 Web 演示测试和 `macro-docs` 文档测试；`typecheck` 会先检查统一入口再检查 Web，`build` 会先生成 `packages/core/dist`，再构建唯一的 `packages/web/index.html` 应用壳。不要在某个子包内单独复制锁文件。

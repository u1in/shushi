# @u1in/shushi：多包工作区说明

> 适用范围：`@u1in/shushi-*` npm workspaces 的组织、依赖边界与本地开发

## 1. 包清单

| 包名 | 责任 | 公共 API |
| --- | --- | --- |
| `@u1in/shushi-core` | 面向 npm 使用者的统一入口，汇总运行时领域包 | `compute*`、`create*MacroSource`、`compileMacro`、`renderDomGrid`、`renderSvgGrid` 以及网格工具 |
| `@u1in/shushi-grid` | 通用行列网格类型与轨道几何 | `GridScene`、`GridElement`、`resolveGridMetrics` 等 |
| `@u1in/shushi-calculators` | 加、减、乘、除、短除法等纯计算过程 | `computeAddition`、`computeSubtraction`、`computeDivision`、`computeMultiplication`、`computeShortDivision` 及计算结果类型 |
| `@u1in/shushi-layout` | 根据运算结果决定竖式结构并生成网格 | 五种 `create*GridScene` 函数及布局设置类型 |
| `@u1in/shushi-renderers` | 把网格渲染为 DOM/CSS 或 SVG | `renderDomGrid`、`renderSvgGrid` |
| `@u1in/shushi-docs` | 框架无关的集中式宏说明、技术文档与图例源 | `macroDocPages`、规则 Markdown |
| `@u1in/shushi-docs-site` | VuePress 发布适配层 | `docs:dev`、`docs:build` |
| `@u1in/shushi-macro-docs` | 网格宏文档的 Vue 页面组件、图例与样式 | `MacroDocsLayout`、`MacroDocPage`、`MacroDocBlocks` 等 |
| `@u1in/shushi-web` | Vue Router 页面、命名图谱、Tailwind 主题和 Vite 前端应用 | 页面入口，不作为其他领域包的依赖 |

根工作区包名为 `@u1in/shushi`，应用与文档包保持私有；`@u1in/shushi-core` 是面向 npm 发布的统一入口。它在构建时把运行时领域包汇总为单一 ESM 文件和单一类型声明入口。源码中的各领域导入统一使用 `@u1in/shushi-*` 命名，`@u1in/shushi` 仅作为工作区根包名。

## 2. 依赖与数据流

```text
@u1in/shushi-calculators ──计算过程──┐
                                             ↓
@u1in/shushi-grid ←──── @u1in/shushi-layout
          ↑                                      ↓ GridScene
          └──── @u1in/shushi-renderers ──┘
                         ↑
                 @u1in/shushi-web
```

- `calculators` 与 `grid` 是底层纯 TypeScript 包，不能导入浏览器 API。
- `layout` 只根据计算结果和布局设置构建 `GridScene`，不创建 DOM 或 SVG。
- `renderers` 只读取 `GridScene`，不含除法、乘法、进位或借位等规则。
- `web` 负责 Vue 页面状态、Vue Router 路由和页面组件；`packages/web/index.html` 是唯一 Vite 应用壳，页面实现均位于该包。
- `docs` 保存框架无关的文档正文、宏内容清单和图例数据；`macro-docs` 依赖 `docs`、`macro`、`grid` 与 `renderers`，提供宏文档 Vue 展示组件与文档专用 SVG 预览；`docs-site` 负责 VuePress 发布；`web` 只负责主应用外壳、兼容宏文档入口和图例交互视图，不再维护图例说明正文。

## 3. 新增代码的位置

- 新运算算法和结果类型：`packages/calculators/src/`；同时更新对应的中文计算规则文档。
- 新运算的布局引擎与布局设置：`packages/layout/src/`；同时更新对应的中文竖式排版规则文档。
- 共享网格契约或轨道几何：`packages/grid/src/`；同时更新 [`网格架构.md`](../grid/网格架构.md)。
- 通用 SVG / DOM/CSS 绘制能力：`packages/renderers/src/`；同时检查两个渲染器和通用架构文档。
- 页面交互或主题：`packages/web/src/`；需要新的页面时新增 Vue 路由页，不新增 HTML 入口。命名图谱的说明数据和字段注释应先写入 `packages/docs/src/gallery/`，Web 页面只读取并渲染。
- 网格宏文档内容：`packages/docs/src/macro/`；说明图例或文档交互：`packages/macro-docs/src/`；修改后运行文档测试，并分别检查主应用 `/macro-rules`、`/macro-api` 与 `npm run docs:build`。

首页网格宏试验区（`MacroPlayground`）的示例以紧凑源码维护在 `macroPlaygroundExamples.ts`，首次载入和切换示例时统一经 `formatMacro` 格式化为多行源码；工具栏仍提供“格式化 / 去格式化”手动切换；快速插入面板默认收起，可按需展开。测试会校验格式化前后的编译场景一致。

`GridPreview` 是首页计算器共享的画板宿主。它在 `division-stage` 相对定位容器内同时挂载 SVG 与 DOM/CSS 网格：该容器保证绝对定位图元以同一组 `GridScene` 尺寸为坐标系，SVG 节点保留 `division-svg` 样式类以复用语义 token 的字体、颜色和线条主题。修改这个宿主结构时，必须同时检查两种渲染模式。

每个首页计算器都通过 `StepPlaybackControls` 独立检查自己的过程；“开始 / 上一步 / 下一步”改变布局设置中的 `visibleStepCount`，“结束”恢复未设置游标的完整场景。控制器不重算、不修改计算器过程 JSON，只请求布局层重新生成当前步骤的 `GridScene`。

首页每个运算板块的 OCR 按行结果由 `VisibleTextRowsPanel` 作为独立的第三列面板显示在计算结果右侧；宽屏保持最右侧，窄屏自动落到工作区下一行。面板默认展开并在场景更新时实时刷新，按钮可收起或重新展开 JSON 输出。

各运算元素命名图谱使用 `NamingMapGrid` 展示语义高亮，并配合集中式图例数据提供名称、语义 token 和简短说明。图例页不展示计算结果 JSON、`GridScene` 数据或渲染器字段；这些内容属于技术文档和开发调试范围。

## 4. 开发与验证

在 WSL 中先加载 fnm 环境，然后从仓库根目录运行：

```bash
source ~/.zshrc
npm install
npm run typecheck
npm run test
npm run build
```

根目录的 `dev`、`test` 仍服务于 `packages/web`；`typecheck` 会先检查统一入口再检查 Web，`build` 会先生成 `packages/core/dist`，再构建唯一的 `packages/web/index.html` 应用壳。不要在某个子包内单独复制锁文件。

# 除法计算规则

> 版本：V12.5<br>
> 适用范围：@u1in/shushi 的除法器小数输入校验、逐位长除法和渲染数据流

本文件以 `deepseek_html_20261028_7a4ad6.html` 为规则来源，保留项目既定的“字符串逐位运算、不使用大数类型”实现约束。竖式坐标与 CSS 线条见 [`除法竖式排版规则.md`](../layout/除法竖式排版规则.md)。

## 1. 术语与入口约束

| 术语   | 代码名称             | 约束                               |
| ------ | -------------------- | ---------------------------------- |
| 被除数 | `dividendText` / `D` | 非负十进制数                       |
| 除数   | `divisorText` / `d`  | 正十进制数                         |
| 商     | `quotientText` / `q` | 非负整数，配置小数位时可为截断小数 |
| 余数   | `remainder` / `r`    | `0 <= r < d`                       |

- 处理非负十进制数除以正十进制数；负数、空值和其他格式必须报错，不得静默转换。
- 计算前先把除数的小数点右移为整数，被除数同步右移相同位数；若被除数小数位不足，必须在其右侧补 `0` 至所需位数。例如 `0.250 ÷ 0.0005` 的过程数字为 `02500 ÷ 5`，等值过程文本为 `2500 ÷ 5`。`divisorDigits` 与 `dividendDigits` 保存这份去点逐位过程，`divisorText` 与 `dividendText` 保存等值变换后的过程文本。`sourceDivisorText` 与 `sourceDividendText` 保存原始输入，供竖式输入行保留现场并标记变换。
- 输入中的前导 `0` 在计算前移除；零规范化为字符串 `"0"`。
- 整段输入、当前部分被除数、乘积和余数都保存为数字字符串，不能转为 `Number`、`BigInt` 或其他大数类型。
- 单个字符数字可短暂转为 `Number`，仅用于逐位乘法进位、借位和比较。

## 2. 核心不变量

输入不含小数时，整数阶段必须满足：

```text
D = d × q + r
0 <= r < d
```

配置并计算出 `n` 位小数后，若仍有余数，则结果满足 `D = d × q + r / 10^n`；`q` 为当前显示的小数商。实现以字符串逐位完成比较、乘以一位数和减法；因此数字长度不受 JavaScript 安全整数范围限制。

## 3. 逐位长除法

从被除数最高位向最低位遍历，维护滚动余数 `remainder`：

```text
current   = remainder 右侧拼接 nextDigit，并移除前导 0
qd        = 使 divisor × qd <= current 的最大一位数（0..9）
product   = divisor × qd
remainder = current - product
```

- `qd` 通过从 `9` 向 `0` 的一位试商取得，`product` 和减法均为字符串逐位运算。
- 商尚未开始且 `qd = 0` 时，只更新余数，不写前缀商位或竖式步骤；若遍历结束后商仍未开始，则补写整商唯一的 `0`，并记录 `当前部分被除数 − 0` 的竖式步骤。
- 商开始后，每轮都写入商位；中间与末尾的 `0` 都必须保留。
- 商开始后的每一轮都写入商位；中间与末尾的 `0` 都必须保留。
- 商开始后的每一轮（包括 `qd = 0`）都必须写入 `steps`；渲染层通过独立开关决定是否显示这些零商步骤，默认不显示。整商为 `0` 时补记的最后一步同样属于 `steps`，也受该开关控制。
- 每一轮在 `steps` 中记录 `dividendColumn`、`divisor`、`quotientDigit`、`partialDividend`、`product` 与 `remainder`。每个步骤都可以独立检查：`partialDividend = divisor × quotientDigit + remainder`。
- 播放某一步时，计算与布局必须只消费该步及其之前的前缀：当前输入、当前余数、已写商位和已补零都应能单独验证；后续试商、循环展开位、最终余数和截断状态不得参与当前帧的计算或列宽。

## 4. 计算层输出契约

`packages/calculators/src/division.ts` 只负责字符串长除法，导出不包含像素、行号或 DOM/SVG 信息的 `DivisionComputation`。它是计算层和竖式排版层之间唯一的中间过程：

| 字段                                       | 含义                                                                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `quotientTokens`                           | 商的语义 token；数字为 `{ kind: "digit", digit, column }`，小数分隔符为 `{ kind: "decimalSeparator", digit: ".", column }`。小数点附着在整数末位同一显示列的右侧。 |
| `sourceDivisorText` / `sourceDividendText` | 规范化前的输入文本。布局必须以它们书写输入行，不能把等值整数过程伪装成用户原始算式。                                                                               |
| `normalizationShift`                       | 为使除数成为整数而同步右移的位数；每一位右移由计算器写入 `calculationSteps` 的等值变换快照。                                                                       |
| `divisorText` / `dividendText`             | 除数右移为整数、被除数同步右移（不足位数在右侧补 `0`）后的等值过程文本，用于逻辑列、试商与过程行对齐。                                                             |
| `integerDividendDigitCount`                | `dividendText` 的整数数字列数；商点在其末位完成后出现。                                                                                                            |
| `steps`                                    | `LongDivisionStep[]`；每项是一次计算层的“部分被除数 − 乘积”运算，包含商位为 `0` 的步骤；是否可见由排版开关决定。                                                   |
| `fractionalDigitCount`                     | 已实际计算并追加到被除数右侧的 `0` 列数；有限小数和被截断的小数均计入。                                                                                            |
| `digitColumnCount`                         | 被除数和已追加的小数数字列总数；小数点由布局层定位在相邻数字列的边中点，不额外占用数字列。                                                                         |
| `calculationSteps`                         | `CalculationStepSnapshot[]`；按等值右移、商小数点和每轮试商顺序返回。每项只含当前已产生的商和余数，布局只截取其前缀。                                              |
| `integerStartColumn`                       | 第一位整数商的来源列；整商为 `0` 时为 `-1`。                                                                                                                       |
| `decimalTruncated`                         | 配置了 `maxDecimalDigits` 且达到该位数后余数仍不为 `0` 时为 `true`；此前各步小数过程和当前余数均保留在输出中。                                                     |

竖式排版必须只消费上述过程，不能重新试商、相减或自行判断小数循环。渲染坐标与视觉元素由 [`除法竖式排版规则.md`](../layout/除法竖式排版规则.md) 定义。

## 5. 规则明细

### R1 前导零不写

商的第一位不能为 `0`，除非整个商就是 `0`。例如 `102 ÷ 3` 中第一位 `1` 不够除时跳过，商从 `10 ÷ 3 = 3` 开始。

### R2 商位对齐且位数受限

每个商位对齐到产生该商位的被除数数字列；商位数不超过被除数位数。

### R3 余数范围

每轮计算后均有 `0 <= remainder < divisor`。若余数不小于除数，则试商或减法有误。

### R4 中间和末尾的零

只有前导零可省略。`1040 ÷ 5 = 208`、`60 ÷ 3 = 20`、`608 ÷ 2 = 304` 中的零都必须写在商内。

### R5 商开始后的零商位记录与可选渲染

商已开始后，`qd = 0` 仍需写商位，并在 `steps` 中完整记录当前部分被除数、乘积 `0`、余数和对应减法步骤。竖式排版提供“显示试商为 0 的步骤”开关，默认关闭；关闭时只隐藏这些步骤，不能从计算结果中删除它们。

### R6 被除数小于除数与零

- `D < d`：商为 `0`，余数为 `D`。
- `D = 0`：商为 `0`，余数为 `0`。
- 若遍历结束后商仍未开始（包括 `D = 0` 和 `D < d`），必须补记最后一轮 `当前部分被除数 − 0`。该步骤保存在 `steps` 中，是否绘制由“显示试商为 0 的步骤”开关决定。
- `d = 1`：商等于被除数，余数为 `0`。

### R7 可选的小数位终止

- 原被除数在等值变换后仍有小数位时，先逐位带入这些已有小数数字；首次带入前在商和被除数对应位置写入小数点。
- 已有小数位仍未除尽时，或整数输入有余数时，再从余数右侧逐位补 `0`。未传 `maxDecimalDigits` 时，默认最多补十个 `0`；传入非负整数时以传入值覆盖该补零上限。传入 `0` 时不追加小数位，整数阶段结束后直接保留当前余数。
- 余数提前变为 `0` 时显示有限小数；补出的 `0` 显示在被除数行并使用弱化颜色。
- 到达正数 `maxDecimalDigits` 后余数仍不为 `0` 时立即停止，保留已生成的小数商、过程步骤和当前余数，并将 `decimalTruncated` 标为 `true`。当 `maxDecimalDigits` 为 `0` 时按整数长除法返回余数，不生成小数点或截断小数。不会为了检测循环而回退或继续试算。

### R8 终止条件

未配置小数位时在被除数最后一位处理完毕；配置后在余数为 `0` 或达到指定小数位时结束。最终有效余数无论是否为 `0` 都显示在竖式最底部。

### R9 等值变换的输入保留

当 `normalizationShift > 0` 时，逐位试商仍只使用 `divisorDigits` 与 `dividendDigits`；布局先将同步右移拆成逐帧事件，每帧同时更新除数、被除数及其小数点，完成全部右移后才展示第一轮试商。每次右移都保留上一位置的小数点与被省略的前导 `0`，以删除线表明它们已经越过当前位值；新位置的小数点保持正常显示。若同步右移需要补零，补入的 `0` 在对应帧出现，不能只在最终过程数字中隐含。例如 `0.250 ÷ 0.0005` 依次表示 `0.0005 ÷ 0.250`、`0.005 ÷ 2.50`、`0.05 ÷ 25.0`、`0.5 ÷ 250`、`5 ÷ 2500`，并保留被右移越过的元素删除线，随后按 `02500 ÷ 5` 试商。等值变换帧不属于试商、乘积或余数计算。

## 6. 验证清单

| 输入（被除数 ÷ 除数）   | 期望                                   |
| ----------------------- | -------------------------------------- |
| `0 ÷ 5`                 | `q=0, r=0`                             |
| `5 ÷ 5`                 | `q=1, r=0`                             |
| `4 ÷ 5`                 | `q=0, r=4`                             |
| `102 ÷ 3`               | `q=34, r=0`                            |
| `1040 ÷ 5`              | `q=208, r=0`                           |
| `60 ÷ 3`                | `q=20, r=0`                            |
| `100 ÷ 7`               | `q=14, r=2`                            |
| `1000000 ÷ 1000`        | `q=1000, r=0`                          |
| 配置 4 位小数：`1 ÷ 8`  | `q=0.125, r=0, decimalTruncated=false` |
| 配置 2 位小数：`1 ÷ 3`  | `q=0.33, r=1, decimalTruncated=true`   |
| 配置 0 位小数：`15 ÷ 4` | `q=3, r=3, hasFraction=false`          |
| 超长数字串 ÷ `1`        | 商等于输入，余数为 `0`                 |

## 7. 历史规则（可恢复）

### V10.0：零商步骤省略显示

V10.0 曾规定：商已开始后，`qd = 0` 仅显示商位，不绘制乘积、减法线或额外步骤行；当整商为 `0` 时，不记录竖式步骤。当前规则将这些零商步骤保存在 `steps` 中，并以默认关闭的渲染开关恢复旧的视觉效果。

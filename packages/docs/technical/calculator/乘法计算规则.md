# 乘法计算规则

> 版本：V1.5
> 适用范围：@u1in/shushi 的非负十进制乘法器、逐位过程和渲染数据流

本文件定义 `packages/calculators/src/multiplication.ts` 的计算行为。乘法竖式如何映射到可变轨道网格见 [`乘法竖式排版规则.md`](../layout/乘法竖式排版规则.md)。

## 1. 术语与输入约束

| 术语   | 代码名称                   | 约束                                   |
| ------ | -------------------------- | -------------------------------------- |
| 被乘数 | `multiplicandDigits` / `a` | 非负十进制数                           |
| 乘数   | `multiplierDigits` / `b`   | 非负十进制数                           |
| 部分积 | `partialProducts`          | 乘数每一位对应的一行未错位数字及其位移 |
| 积     | `productDigits` / `p`      | 去点后的非负整数过程数字               |

- 接收十进制非负整数字符串或小数字符串；空值、负数、空白及其他格式必须报错，不得静默转换。
- 先收集两数的小数位数、去除小数点，再完全按整数逐位乘法生成部分积和列加法；最终以两者小数位数之和在 `productText` 中恢复小数点。
- 首页演示输入框按用户输入顺序称为“第一个乘数”和“第二个乘数”；计算层随后仍按竖式展示需要，将两个输入规范化为 `multiplicandDigits` 与 `multiplierDigits`，这两个内部名称描述的是规范化后的行角色而不是输入框标签。
- 输入前导 `0` 在计算前移除，零规范化为字符串 `"0"`。
- 整段数字、部分积和最终积均用字符串保存，不得把整段数字转换为 `Number`、`BigInt` 或其他大数类型。
- 单个数字字符以及单列合计可暂时转为 `Number`，仅用于一位乘法、进位和一列求和。

## 2. 核心不变量

任意完整计算必须满足：

```text
p = a × b
```

其中每个部分积 `partialProducts[i]` 满足：

```text
partialProducts[i].value × 10 ^ partialProducts[i].shift
  = a × 当前乘数位的数值 × 10 ^ shift
```

常规计算中，`shift` 从乘数个位算起：个位为 `0`、十位为 `1`、百位为 `2`，最终积由所有带位移的部分积按列相加得到。末尾补零快捷计算中，`partialProducts` 改为两个有效乘数的基础积过程，按列相加后再补回两个乘数末尾零位总数 `trailingZeroCount` 个零；两种路径都不受 JavaScript 安全整数范围限制。

## 3. 操作数输入顺序

乘法器从不为了“大数在上”、位数或 10 的倍数快捷计算交换操作数：第一个输入始终是第一行 `multiplicandDigits`，第二个输入始终是第二行 `multiplierDigits`。即使较小数字在上方，仍以该顺序生成正确的部分积、位移和最终积；`operandsSwapped` 为兼容已有调用方保留，始终为 `false`。`preserveOperandOrder` 也仅为兼容已有调用方保留，不再改变行为。布局层不重新比较数字，渲染器只消费已经确定的 `GridScene`。

## 4. 逐位乘法

乘数从右向左遍历。对每个乘数位，令 `carry = 0`，被乘数从右向左逐位计算：

```text
total      = 当前被乘数位 × 当前乘数位 + carry
resultDigit = total % 10
carry       = floor(total / 10)
```

- `resultDigit` 从右向左写入该部分积。
- 最后一位后若 `carry > 0`，将它写到部分积左侧。
- 如果这是被乘数最左位的最后一步，产生的 `carry` 只写入部分积左侧作为最高位，不再额外绘制进位符号；只有还会传给下一位乘法的进位才属于可见进位标记。
- 每次逐位计算都记录 `MultiplicationDigitStep`：被乘数位索引、两个数字、进位输入、`total`、写下的数字和进位输出。
- `digitSteps` 按被乘数从左到右的阅读顺序导出；每步的 `carryOut` 是其右侧相邻位传入该步的进位，最左一步的 `carryOut` 是部分积新增的最高位。

## 5. 部分积错位与按列相加

常规计算中，每一个第二行乘数位都生成一个 `MultiplicationPartialProduct`；末尾补零快捷计算中，则由去掉**两个乘数**末尾零后的有效数字生成基础过程：

| 字段                   | 含义                                                 |
| ---------------------- | ---------------------------------------------------- |
| `multiplierDigitIndex` | 当前乘数位在规范化乘数字符串中的左起零基索引         |
| `multiplierDigit`      | 当前参与逐位乘法的数字字符                           |
| `shift`                | 当前位从右起的位置；只表达十进制错位，不包含网格坐标 |
| `value`                | 不补位、不含位移的部分积数字字符串                   |
| `digitSteps`           | 该部分积的逐位乘法与进位过程                         |

计算器再从所有部分积的最右列向左列加：

```text
total       = 所有对齐部分积的当前列数字之和 + carry
resultDigit = total % 10
carry       = floor(total / 10)
```

每列生成一条 `MultiplicationAdditionStep`，记录 `columnFromRight`、各部分积在这一列的 `addendDigits`、进位、`total`、结果数字和下一列进位。这里的列号是算术位值，不是网格坐标。

当最高位相加产生进位时，该进位会在下一列成为最终积的最高位数字；它同时会作为教学标记显示在求和横线上。

## 6. 10 的倍数快捷计算

`computeMultiplication` 的第三个参数为 `MultiplicationOptions`。`useTrailingZeroShortcut` 默认开启；关闭后恢复完整逐位乘法，但仍严格保留输入顺序。`preserveOperandOrder` 为兼容已有调用方保留，不再改变行为。

- 快捷计算分别拆除第一行和第二行乘数**末尾连续的零**，中间零不能省略。例如 `1230 × 200` 先按 `123 × 2` 计算；`7 × 1010` 只可拆除第二行最后一个零，仍须按 `7 × 101` 计算。
- 拆分结果写入 `trailingZeroShortcut`：`significantMultiplicandDigits`、`multiplicandTrailingZeroCount`、`significantMultiplierDigits` 和 `multiplierTrailingZeroCount` 分别记录两行的基础数字和移出的零位；`trailingZeroCount` 是两行零位数之和。未使用快捷计算时该字段为 `null`。
- `partialProducts` 与 `additionSteps` 只描述两个有效数字的基础计算；`productDigits` 始终是补零后的真实最终积。
- 零本身不启用快捷计算，避免产生没有有效位的过程。
- 例如 `1230 × 200` 的基础过程只计算 `123 × 2`，得到 `246`；两行分别移出 `1` 和 `2` 个零，因此最终积补 `3` 个零得到 `246000`。补零属于完成基础过程后的表示步骤，不参与逐位乘法或部分积求和。
- `partialProducts` 与 `additionSteps` 永远按基础算式完整给出，不会因为启用快捷计算而删除：`970 × 890` 仍以 `97 × 89 = 8633` 生成 `873`、`776` 两条部分积和按列求和过程，只在最后补三个零得到 `863300`。

## 7. 零与特殊情况

- 被乘数为 `0` 时，所有部分积为 `0`，最终积为 `0`。
- 乘数为 `0` 时，规范化后只有一个个位部分积 `0`，最终积为 `0`。
- 乘数中间的 `0` 仍须生成值为 `"0"` 的部分积，并保留它对应的 `shift`；排版层据此保留正确位置，不能跳过。
- 部分积不是可随意去除前导零的普通文本。只要一条部分积并非全零，就必须保留每个逐位结果数字；尤其是最高位结果为 `0`、但该步向更高位产生进位时，这个 `0` 仍是有效数位。例如 `35.2 × 1.3` 去点后计算 `352 × 13`，个位部分积必须为 `1056`，不能写成 `156`。仅当该部分积的所有逐位结果均为 `0` 时，排版层才可将其压缩为单个 `0`。
- 未启用快捷计算时，乘数末尾的 `0` 自然生成个位（或低位）的零部分积，后续部分积按 `shift` 错位。
- 最终积不写前导 `0`；例如计算中间得到 `0123` 时，输出为 `"123"`。

## 8. 计算层输出契约

`MultiplicationComputation` 是计算层与乘法排版层之间唯一的中间过程，不能含行号、列号、像素、DOM 或 SVG 数据：

```ts
{
  multiplicandDigits: string,
  multiplierDigits: string,
  multiplicandText: string,
  multiplierText: string,
  multiplicandDecimalPlaces: number,
  multiplierDecimalPlaces: number,
  decimalPlaces: number,
  operandsSwapped: boolean,
  productDigits: string,
  productText: string,
  trailingZeroShortcut: {
    significantMultiplicandDigits: string,
    multiplicandTrailingZeroCount: number,
    trailingZeroCount: number,
    significantMultiplierDigits: string,
    multiplierTrailingZeroCount: number,
  } | null,
  partialProducts: MultiplicationPartialProduct[],
  additionSteps: MultiplicationAdditionStep[],
}
```

排版层可以读取 `shift`、进位和最终积安排竖式，但不得重新执行逐位乘法或按列求和。渲染坐标、横线和样式 token 由 [`乘法竖式排版规则.md`](../layout/乘法竖式排版规则.md) 定义。

## 9. 验证清单

| 输入（被乘数 × 乘数） | 期望部分积 / 积                                                           |
| --------------------- | ------------------------------------------------------------------------- |
| `145 × 12`            | `290 (shift 0)`、`145 (shift 1)`，积 `1740`                               |
| `123 × 101`           | `123 (shift 0)`、`0 (shift 1)`、`123 (shift 2)`，积 `12423`               |
| `145 × 2`             | `290`，积 `290`                                                           |
| `145 × 0`             | `0`，积 `0`                                                               |
| `0 × 12`              | 保持 `0 × 12`：两个零部分积，积 `0`                                       |
| `10 × 24`             | 保持输入顺序；默认只计算 `1 × 24`，补一个零得到 `240`                     |
| `7 × 120`             | 默认计算 `7 × 12`，补一个零得到 `840`                                     |
| `1230 × 200`          | 基础过程 `123 × 2 = 246`，两行共补三个零得到 `246000`                     |
| `970 × 890`           | 基础过程 `97 × 89 = 8633`（部分积 `873`、`776`），共补三个零得到 `863300` |
| 超长数字串 × `1`      | 积等于原数字串                                                            |

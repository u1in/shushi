# 乘法竖式与通用网格排版规则

> 版本：V2.0<br>
> 适用范围：@u1in/shushi 中乘法器的竖式坐标、网格场景、DOM/CSS 与 SVG 对照渲染

整数逐位乘法和过程数据见 [`乘法计算规则.md`](../calculator/乘法计算规则.md)。本文件只定义 `MultiplicationComputation` 如何编排为通用网格，不在渲染器中实现乘法规则。交互式元素命名图谱见图例文档入口。

## 1. 分层与职责

```text
MultiplicationComputation → createMultiplicationMacroSource → compileMacro → GridScene → DOM / SVG renderer
```

- `packages/calculators/src/multiplication.ts` 输出字符串数字、逐位进位、部分积、十进制位移和按列求和过程。
- `packages/layout/src/multiplication-layout.ts` 读取这些过程数据，填写 `GRID`、`ROW`、`CELL`、`RB` 和 `LINE`；兼容 API `createMultiplicationGridScene` 只会编译生成源码，不能直接组装网格。
- `GridScene` 仍是完全通用的可变轨道场景，不理解被乘数、部分积或进位。
- `packages/renderers/src/dom-grid-renderer.ts` 与 `packages/renderers/src/svg-grid-renderer.ts` 只消费 `GridScene`；它们不得判断乘数位或重新计算进位。

## 2. 网格轨道与对齐

普通数字列宽为 `1u`，其中 `u = cellWidth`。最左另设 `0.72u` 的运算符列，乘号 `×` 位于该列的乘数行。常规计算的数字区域列数取被乘数、乘数、部分积（含 `shift`）和最终积所需宽度的最大值；相邻数字列的真实公共边界直接供进位使用。

- 常规竖式中，被乘数、乘数和最终积的最后一位均与数字区域最右列对齐。`trailingZeroShortcut` 非空时，先以被乘数、有效乘数、基础积和部分积确定**基础右边界**；被乘数、有效乘数、基础积、部分积及其进位、求和横线都对齐到这条边界。例如 `97 × 800` 先按 `97 × 8 = 776` 排列，`8` 与 `97` 的 `7` 对齐；`97 × 890` 先按 `97 × 89 = 8633` 排列，有效乘数 `89` 的个位仍落在基础右边界上。
- 快捷计算完成后，在基础右边界的右侧新增 `trailingZeroCount` 条数字轨道，同时在第二行乘数和最终积后各写入同数目的 `0`。因此 `97 × 800` 显示为第一行 `97`、第二行 `800`、最终积 `77600`；`97 × 890` 显示为第一行 `97`、第二行 `890`、基础部分积 `873` 与 `776`、求和横线和最终积 `86330`。新增零位只向右延伸，不移动已排好的数字或横线左端，乘法横线随数字区域延长到新的右边界。
- 布局层接收的操作数已由计算层规范化：关闭快捷计算时始终较大操作数在第一行；启用快捷计算且恰有一个操作数为非零 10 的倍数时，它优先作为第二行 `multiplierDigits`。
- 一个部分积的最后一位对齐到数字区域最右列 `- shift`（快捷计算时改为基础右边界 `- shift`）；因此个位部分积右对齐，十位部分积左移一格，百位部分积左移两格。
- 数字区域列数先由布局层完整计算。渲染器不能为对齐目的测量 DOM 或修改轨道。

## 3. 行结构

```text
Row 0：被乘数
Row 1：× 乘数（下边为乘法横线）
重复：Row：部分积（上边可放本位进位）
最后 Row：最终积（上边可放加法进位和求和横线）
```

- 只有一个乘数位时，唯一的部分积就是最终积，不重复绘制一行，也没有求和横线。
- 乘数有多位时，所有部分积（包括值为 `0` 的部分积）依 `shift` 绘制；最后一条部分积下方绘制求和横线，下一行绘制最终积。
- 乘法横线是乘数行的 `bottom edge`，求和横线是最终积行的 `top edge`；两者是既有内容行之间的边界，因此 `showCarrySteps` 不会改变网格高度或线的位置。
- 每条部分积上方的本位进位都定位到“目标数字列右边界 × 部分积行上边界”的 `intersection`。进位文本同时使用 `horizontalAlign: "center"` 和 `verticalAlign: "bottom"`：水平方向骑在两列边界上，垂直方向从行边界向上延伸，占用上一行下半部的留白，而不消耗额外行高。
- 多位乘数的加法进位同样放在最终积行上边界的 `intersection`。最高位相加产生的进位既进入最终积的最高位，也会在求和横线上显示，用来解释最高位是如何形成的。
- 求和横线只在部分积按列相加的首步开始后绘制；在逐位生成部分积的阶段不得提前呈现横线。
- `showCarrySteps` 只控制进位文本元素；计算层的 `digitSteps` 与 `additionSteps` 不受影响，所有轨道始终为正尺寸。
- 进位文本使用 `fontSizeRatio: 0.42`，即按 `GridScene.fontSize` 缩小为教学标记。该属性是通用文本单元格能力，DOM/CSS 与 SVG 渲染器以相同方式处理，不包含任何乘法专属判断。
- 进位向上延伸会占用上一行下缘的留白。它水平位于两列之间，默认不会压住数字；但 `fontSizeRatio` 很大或行高很小时，进位仍可能侵入相邻数字的横向空间。这是该排版技巧的预期取舍，需要在极端参数下目检。
- 进位只显示在它还将参与下一高位计算的位置；最左位最后一步产生的进位只作为部分积新增的最高位，不绘制独立进位符号。
- 乘法横线覆盖运算符列和全部数字区域；求和横线覆盖数字区域。两条横线都由跨列 `GridElement.position.kind = "edge"` 和 `line` 内容绘制，渲染器不会创建运算专属线段。
- `uniformMultiplicationBars` 开启时，求和横线扩展到运算符列，使它与乘法横线同起点、同终点、同宽；关闭时保留默认教学排版，即乘法横线含运算符列、求和横线只覆盖数字区域。
- `trailingZeroShortcut` 非空时仍保留基础算式的完整过程：有效乘数为多位（如 `97 × 890`、`7 × 120`）时，部分积、求和横线和进位都按基础算式绘制，补零只出现在乘数行和最终积行的右侧。只有有效乘数仅一位（如 `24 × 10`、`97 × 800`）时没有部分积阶段，才直接在乘法横线下绘制已补零的 `productDigits`，固定为“24 / × 10 / 横线 / 240”的三行形式。

## 4. `GridElement` 与语义样式

文本均使用 `GridElement.content.kind = "text"`；横线使用 `GridElement.position.kind = "edge"` 与 `content.kind = "line"`。乘法专用 token 由布局层填写：

| token | 用途 |
| --- | --- |
| `multiplication.multiplicand` | 被乘数 |
| `multiplication.multiplier` | 乘数 |
| `multiplication.operator` | 乘号 `×` |
| `multiplication.carry` | 逐位乘法行列交点上的小号进位提示（水平居中、向上延伸） |
| `multiplication.addition-carry` | 部分积相加时的小号进位提示（水平居中、向上延伸） |
| `multiplication.partial-product` | 多位乘数产生的部分积 |
| `multiplication.product` | 最终积；一位乘数时也承载唯一部分积 |
| `multiplication.input-bar` | 乘数行下的乘法横线 |
| `multiplication.sum-bar` | 多位乘数的部分积求和横线 |

`packages/web/src/styles/main.css` 只按上述 token 着色；DOM/CSS 与 SVG 均复用相同 token。文本的水平/垂直对齐未在单元格覆盖时，继承 `GridScene.textHorizontalAlign` 与 `GridScene.textVerticalAlign`。`showGuideGrid` 覆盖所有已解析轨道，用于检查错位，不属于乘法计算过程。

## 5. 示例：145 × 12

计算层导出：

```text
部分积 290，shift 0（5 × 2 时向十位进 1）
部分积 145，shift 1
最终积 1740
```

布局得到的阅读结构为：

```text
      145
×      12
─────────
      290
     145
─────────
     1740
```

进位、部分积和最终积的精确列均由 `shift` 和 `digitSteps` 推导；示意中的空格不表示像素坐标。首个部分积的进位 `1` 绘制在乘数 `12` 的十位与个位之间的真实列边界上；它与横线共享边界，不额外占用行高，上图省略了这条进位标记。

## 5.1 步骤检查

`MultiplicationRenderSettings.visibleStepCount` 的前半段对应每一条 `digitSteps`：先从个位到最高位完成当前乘数位的部分积，再处理下一乘数位；每完成一位，只在该部分积行写入该位的结果数字及已产生的进位。部分积完整后，才开始下一行。后半段对应部分积按列求和，按个位到高位渐进显示最终积和求和横线；未设置时显示完整竖式。进位标记只跟随已经显示的步骤出现。`trailingZeroShortcut` 非空时，播放按有效乘数进行：先完成逐位乘法，多位有效乘数随后还有基础积的按列求和；完成前第二行仅显示有效乘数，完成时才在乘数行和最终积行右侧一次补回零位。

## 6. 同步与验证

修改列宽、交点进位位置、行结构、错位、进位的向上延伸方向、横线、token、`GridScene` 或任一渲染器时，必须同步更新本文件；同时检查 [`网格架构.md`](../grid/网格架构.md) 是否需要反映共享契约变化。

完成后至少运行：

```bash
source ~/.zshrc
npm run typecheck
npm run test
npm run build
```

# 乘法竖式与通用网格排版规则

> 版本：V2.4<br>
> 适用范围：@u1in/shushi 中乘法器的竖式坐标、网格场景、DOM/CSS 与 SVG 对照渲染

整数逐位乘法和过程数据见 [`乘法计算规则.md`](../calculator/乘法计算规则.md)。本文件只定义 `MultiplicationComputation` 如何编排为通用网格，不在渲染器中实现乘法规则。交互式元素命名图谱见图例文档入口。

## 1. 分层与职责

```text
MultiplicationComputation → createMultiplicationMacroSource → compileMacro → GridScene → DOM / SVG renderer
```

- `packages/calculators/src/multiplication.ts` 输出字符串数字、逐位进位、部分积、十进制位移和按列求和过程。
- `packages/layout/src/multiplication-layout.ts` 读取这些过程数据，填写 `GRID`、`ROW`、`CELL`、`RT`、`RB` 和 `LINE`；兼容 API `createMultiplicationGridScene` 只会编译生成源码，不能直接组装网格。
- `GridScene` 仍是完全通用的可变轨道场景，不理解被乘数、部分积或进位。
- `packages/renderers/src/dom-grid-renderer.ts` 与 `packages/renderers/src/svg-grid-renderer.ts` 只消费 `GridScene`；它们不得判断乘数位或重新计算进位。

## 2. 网格轨道与对齐

普通数字列宽为 `1u`，其中 `u = cellWidth`。最左另设 `0.72u` 的运算符列，乘号 `×` 位于该列的乘数行。常规计算的数字区域列数取被乘数、乘数、部分积（含 `shift`）和最终积所需宽度的最大值；相邻数字列的真实公共边界直接供进位使用。

- 常规竖式中，被乘数、乘数和最终积的最后一位均与数字区域最右列对齐。`trailingZeroShortcut` 非空时，先以两个有效乘数、基础积和部分积确定**基础右边界**；两个有效数字的个位、部分积及其进位、求和横线都对齐到这条边界。
- 快捷计算时，第一行和第二行各自移出的零从基础右边界向右连续写入，保留在其有效数字个位的右侧；最终积在基础积后补两行零位数之和 `trailingZeroCount` 个零。因此 `1230 × 200` 显示为第一行 `1230`、第二行 `200`、最终积 `246000`：`3`、`2` 与 `6` 都位于基础右边界，第一行 `0` 与第二行第一个 `0` 位于其右一列，最终积的最后一个 `0` 才是新的右边界。布局使用 `EMPTY()` 补足尚未写入数字的右侧单元格，乘法横线仍延长到最终数字区域右边界。
- 布局层不重新比较或交换操作数：无论数值大小、位数或是否启用 10 的倍数快捷计算，第一个输入始终在第一行，第二个输入始终在第二行；即使小数在上，部分积、进位和最终积仍按相同网格规则计算与排版。
- 小数乘法的两行输入与最终积分别从 `multiplicandText`、`multiplierText` 和 `productText` 恢复小数点；点通过该行整数个位的 `DOT` 图元附着在右侧，不占独立数字列。部分积和逐位进位继续只使用去点后的整数过程。为避免把小数位中的零误当作十倍数快捷计算，小数输入不会启用末尾零快捷规则。
- 一个部分积的最后一位对齐到数字区域最右列 `- shift`（快捷计算时改为基础右边界 `- shift`）；因此个位部分积右对齐，十位部分积左移一格，百位部分积左移两格。
- 数字区域列数先由布局层完整计算。渲染器不能为对齐目的测量 DOM 或修改轨道。

## 3. 行结构

```text
Row 0：被乘数
Row 1：× 乘数（下边为乘法横线）
重复：Row：部分积（上边可放本位进位）
最后 Row：最终积（上边可放加法进位和求和横线）
```

- 只有一个乘数位时，唯一的部分积就是最终积，不重复绘制一行，也没有求和横线。
- 乘数有多位时，所有部分积（包括值为 `0` 的部分积）依 `shift` 绘制；最后一条部分积下方绘制求和横线，下一行绘制最终积。
- 写入非全零部分积时，必须逐位保留 `digitSteps` 的所有结果数字，不能按字符串前导零规则裁剪。最高位为 `0` 但会向左产生进位时，该零仍需显示：`35.2 × 1.3` 的去点过程 `352 × 13` 中，个位部分积应显示 `1056`。只有一条部分积的所有已完成结果数字都是 `0` 时，才将它压缩为单个 `0`，避免空白过程行。
- 乘法横线是乘数行的 `bottom edge`，求和横线是最终积行的 `top edge`；两者是既有内容行之间的边界，因此 `showCarrySteps` 不会改变网格高度或线的位置。
- 每条部分积的本位进位默认以左侧一位目标数字为锚点，使用该数字同一个 `CELL` 中的公开 `RT(text)`，即右上角小号文字。若该过程行紧接一条 `LINE`，进位改附着在该列上方数字的 `RB(text)`，落在横线的上侧；这样不会压到横线后的过程数字。
- 多位乘数的加法进位遵循同一规则。最终积紧接求和横线，所以它们使用最后一条部分积相应数字的 `RB(text)`；最高位相加产生的进位既进入最终积的最高位，也会在求和横线上方显示，用来解释最高位是如何形成的。
- 求和横线只在部分积按列相加的首步开始后绘制；在逐位生成部分积的阶段不得提前呈现横线。
- `showCarrySteps` 只控制进位文本元素；计算层的 `digitSteps` 与 `additionSteps` 不受影响，所有轨道始终为正尺寸。
- 进位文本使用 `fontSizeRatio: 0.42`，即按 `GridScene.fontSize` 缩小为教学标记。该属性是通用文本单元格能力，DOM/CSS 与 SVG 渲染器以相同方式处理，不包含任何乘法专属判断。
- 进位向上延伸会占用上一行下缘的留白。它水平位于两列之间，默认不会压住数字；但 `fontSizeRatio` 很大或行高很小时，进位仍可能侵入相邻数字的横向空间。这是该排版技巧的预期取舍，需要在极端参数下目检。
- 进位只显示在它还将参与下一高位计算的位置；最左位最后一步产生的进位只作为部分积新增的最高位，不绘制独立进位符号。
- 乘法横线覆盖运算符列和全部数字区域；求和横线覆盖数字区域。两条横线都由跨列 `GridElement.position.kind = "edge"` 和 `line` 内容绘制，渲染器不会创建运算专属线段。
- 自动生成的乘数行始终以 `EMPTY()` 补足完整网格列宽，因此乘法横线可使用无参数的 `LINE` / `LN`，不额外输出冗余的 `KV(span, full)`：有多条横线时默认 `previous` 已覆盖同一范围；只有一条横线时编译器默认 `full`。只有开启 `uniformMultiplicationBars` 的求和横线仍需显式使用 `full`。
- `uniformMultiplicationBars` 开启时，求和横线扩展到运算符列，使它与乘法横线同起点、同终点、同宽；关闭时保留默认教学排版，即乘法横线含运算符列、求和横线只覆盖数字区域。
- `trailingZeroShortcut` 非空时仍保留基础算式的完整过程：有效第二行乘数为多位（如 `970 × 890`、`7 × 120`）时，部分积、求和横线和进位都按基础算式绘制，补零只出现在两个输入行各自的有效个位右侧与最终积右侧。只有有效第二行乘数仅一位（如 `1230 × 200`）时没有部分积阶段，才直接在乘法横线下绘制已补零的 `productDigits`。

## 4. `GridElement` 与语义样式

文本均使用 `GridElement.content.kind = "text"`；横线使用 `GridElement.position.kind = "edge"` 与 `content.kind = "line"`。乘法专用 token 由布局层填写：

| token                              | 用途                                                                |
| ---------------------------------- | ------------------------------------------------------------------- |
| `multiplication.multiplicand`      | 被乘数                                                              |
| `multiplication.multiplier`        | 乘数                                                                |
| `multiplication.operator`          | 乘号 `×`                                                            |
| `multiplication.carry`             | 逐位乘法目标数字右上角的小号进位提示；横线后首行改用上行数字的 `RB` |
| `multiplication.addition-carry`    | 部分积相加的进位提示；最终积前有求和横线时使用最后部分积数字的 `RB` |
| `multiplication.partial-product`   | 多位乘数产生的部分积                                                |
| `multiplication.product`           | 最终积；一位乘数时也承载唯一部分积                                  |
| `multiplication.decimal-separator` | 输入行和最终积的小数点                                              |
| `multiplication.input-bar`         | 乘数行下的乘法横线                                                  |
| `multiplication.sum-bar`           | 多位乘数的部分积求和横线                                            |

`packages/web/src/styles/main.css` 只按上述 token 着色；DOM/CSS 与 SVG 均复用相同 token。文本的水平/垂直对齐未在单元格覆盖时，继承 `GridScene.textHorizontalAlign` 与 `GridScene.textVerticalAlign`。`showGuideGrid` 覆盖所有已解析轨道，用于检查错位，不属于乘法计算过程。

## 5. 示例：145 × 12

计算层导出：

```text
部分积 290，shift 0（5 × 2 时向十位进 1）
部分积 145，shift 1
最终积 1740
```

布局得到的阅读结构为：

```text
      145
×      12
─────────
      290
     145
─────────
     1740
```

进位、部分积和最终积的精确列均由 `shift` 和 `digitSteps` 推导；示意中的空格不表示像素坐标。首个部分积紧跟乘法横线，因此它的进位 `1` 以乘数同列数字的 `RB(1)` 显示在线上方；它不额外占用行高，上图省略了这条进位标记。

## 5.1 步骤检查

`MultiplicationRenderSettings.visibleStepCount` 的前半段对应每一条 `digitSteps`：先从个位到最高位完成当前乘数位的部分积，再处理下一乘数位；每完成一位，只在该部分积行写入该位的结果数字及已产生的进位。部分积完整后，才开始下一行。后半段对应部分积按列求和，按个位到高位渐进显示最终积和求和横线；小数乘法在所有数字过程结束后额外用一帧补回最终积的小数点。未设置时显示完整竖式。进位标记只跟随已经显示的步骤出现。`trailingZeroShortcut` 非空时，播放按两个有效数字进行：两个输入行从开始就显示各自的末尾零，完成基础过程后才在最终积右侧一次补回零位。

## 6. 同步与验证

修改列宽、交点进位位置、行结构、错位、进位的向上延伸方向、横线、token、`GridScene` 或任一渲染器时，必须同步更新本文件；同时检查 [`网格架构.md`](../grid/网格架构.md) 是否需要反映共享契约变化。

完成后至少运行：

```bash
source ~/.zshrc
npm run typecheck
npm run test
npm run build
```

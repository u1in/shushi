# 除法竖式与通用网格排版规则

> 版本：V21.0
> 适用范围：@u1in/shushi 中除法器的竖式坐标、网格场景、DOM/CSS 与 SVG 对照渲染

整数逐位长除法规则和计算过程见 [`除法计算规则.md`](../calculator/除法计算规则.md)。本文件定义除法如何把计算过程编排为通用网格，不在渲染器中保留除法规则。

## 1. 分层与职责

```text
DivisionComputation → createDivisionMacroSource → compileMacro → GridScene → DOM / SVG renderer
```

- `packages/calculators/src/division.ts` 只产出字符串计算过程和语义商 token，不包含像素、行号或 DOM 信息。
- `packages/layout/src/division-layout.ts` 只负责填写除法宏：可见步骤、对齐、`BRACKET`、`DOT`、`STRIKE`、`STRIKEDOT` 和 `LINE`；兼容 API `createDivisionGridScene` 仅编译生成的源码。
- `GridScene` 是通用渲染契约，由 `columns`、`rows`、`elements`、边距和默认字体配置组成。
- `packages/renderers/src/dom-grid-renderer.ts` 与 `packages/renderers/src/svg-grid-renderer.ts` 只消费 `GridScene`；它们不能判断什么是商、部分被减数或零商步骤。

## 2. 网格轨道与单元格

网格使用可变宽列和可变高行。普通数字列宽为 `1u`，普通行高为 `1h`，其中 `u = cellWidth`、`h = rowHeight`。

| 轨道     | 尺寸   | 用途                               |
| -------- | ------ | ---------------------------------- |
| 数字列   | `1u`   | 除数、被除数、商、乘积、余数和补零 |
| 厂字弯列 | `0.5u` | 除数和被除数之间的厂字弯单元格     |
| 行       | `1h`   | 商、被除数、过程和余数行           |

所有轨道均为正尺寸。厂字横位于被除数行的 `top edge`，减法线位于每个部分减数行的 `bottom edge`；两者直接使用上下内容行的公共边界，不额外占用行轨道。

`GridElement` 是唯一的可绘制图元。元素可承载：

- `text`：数字、符号或小数点；文本可设置自己的 `styleToken`，没有 token 时继承渲染器默认文本样式；
- `corner`：厂字弯等圆角边框；
- `line`：位于 `edge` 位置的直线。减法线和顶部横线均为跨列边元素，而不是运算专属线段。
- `strike`：单元格内具有独立端点和样式 token 的删除线，用于解释等值变换，不依附于数字文字。

单元格可以通过其所在轨道类型提出尺寸要求；轨道尺寸必须由排版层在渲染前确定。渲染器只能读取已完成的 `GridScene`，不得在 DOM 测量后修改行高或列宽。

## 3. 除法坐标映射

计算列和显示列必须分离：

- `dividendColumn` 仅指等值变换后的被除数或补零的逻辑列。
- 每个 `quotientTokens` 项提供对应的逻辑数字列；小数点作为 `{ kind: "decimalSeparator", digit: "." }` 附着在商整数末位的同一单元格右侧，不额外占用数字轨道。
- 排版层将逻辑列仍映射到等值变换后的 `divisorText`、`dividendText`，但输入行写入 `sourceDivisorText`、`sourceDividendText`。当 `normalizationShift > 0` 时，原小数点以 `STRIKEDOT` 显示；除数中被规范化去除的前导零各自使用 `STRIKE`。原被除数仍有小数位时，商点与该整数末位对齐；整数输入补零时，商点和被除数点均在原被除数最后一列右侧显示。
- 因此小数点、补零、后续商位和部分被减数都能在网格中对齐，同时不会污染逐位除法逻辑。

小数点元素通过通用 `DOT` 附着在对应数字单元格右侧；页面上的全局对齐控件不会把它推偏。

## 4. 行结构与除法单元格

```text
Row 0：商数字及（如有）小数点元素
Row：除数、厂字弯单元格、被除数（顶部为厂字横）
Row：首轮部分减数（乘积，底部为减法线）
后续步骤：部分被减数 → 部分减数（底部为减法线）
最后一行：最终余数（包括 0）
```

- 除数按数字单元格右对齐，最右格紧接 `0.5u` 的厂字弯列。
- 被除数、商、部分被减数、部分减数和余数都按逻辑被除数列对齐；多位数右对齐到本轮 `dividendColumn`。
- 首轮部分被减数已在被除数行出现，只绘制首轮部分减数和减法线。
- 厂字弯是一个 `corner` 单元格，方向固定为左下到右上，并使用固定的标准圆角比例；它不提供页面调节控件。DOM/CSS 与 SVG 均使用 2px 锐利线条，弯折半径保持不变。
- 厂字横是被除数行顶部的跨列 `edge`，减法线是每个部分减数行底部的跨列 `edge`；两者线宽均为 `2px`，使用无圆角端点，减法线右端固定于最后一个数字列的右边界。
- “减法横线等宽”开启时，所有减法线使用所有可见步骤中最靠左的逻辑起始列。
- 试商为 `0` 的步骤始终存在于计算输出；“显示试商为 0 的步骤”关闭时，排版层过滤其过程单元格并重新计算行数和总高度。

### 4.1 步骤检查

`RenderSettings.visibleStepCount` 从当前可显示的教学事件由左到右截取。关闭 `showZeroQuotientSteps` 时，试商为 `0` 的乘积、减法线和余数不再渲染；但会生成一个独立的“商补 `0`”事件。该事件只在商行写入 `0`，绝不增加、删除或改写下方的部分被除数、乘积、减法线与余数。下一非零商位的计算事件才更新这些过程行。已完成的商位、部分被除数、部分减数、减法线和当前余数逐步进入 `GridScene`；当前余数按减法规则右对齐到最后一个可见计算步骤的部分被除数末位。

原输入在等值变换后仍带小数位时，输入行的小数点从首帧显示；商点事件发生在整数部分结束、首个输入小数位进入计算前。若输入没有小数，商点与被除数点仍作为独立事件，发生在首个补 `0` 前。网格可预留后续列，但不能提前渲染数字 `0`。

## 5. 小数与样式

`quotientTokens` 中的小数分隔符是语义 token。排版层以通用 `DOT` 把它附着在商整数末位；被除数的输入或补零边界同样使用 `DOT`。除数小数化整数时，`STRIKE` 以左上到右下的相对单元格端点独立覆盖被消去的除数前导零，`STRIKEDOT` 同时覆盖原小数点；数字删除线相对默认跨度按中心缩短约 10%，小数点删除线缩短 50%，避免遮挡相邻字符。颜色由编译阶段写入 `GridScene` 的 `colorTheme.strike` 独立控制，默认 `#949494`，不继承除数或被除数颜色。DOM/CSS 与 SVG 只渲染通用图元，不判断除法语义。两者均由宏源码复刻，不依赖像素坐标或渲染器分支。

边和圆角使用 `GridElement.styleToken`，文本使用 `GridTextContent.styleToken`。例如除数文本使用 `division.divisor`，减法线元素使用 `division.subtraction-bar`。没有指定 token 的文本继承 `GridScene.defaultTextStyleToken` 的渲染配置；未配置该默认 token 时才回退到渲染器的基础颜色和字重。文本、直线和圆角都可携带通用的 `color`，直线和圆角还可携带 `thickness` 覆盖值，供宏语言等通用输入使用；除法布局继续仅使用既有语义 token，因此外观和计算规则不变。文本的 `horizontalAlign` / `verticalAlign` 可在元素内单独覆盖；没有覆盖值时分别继承 `GridScene.textHorizontalAlign` / `textVerticalAlign`。这允许未来的加法、乘法共享渲染器并各自定义教学样式。

辅助网格是 `GridScene.showGuideGrid` 对应的渲染器调试能力。它覆盖所有已解析轨道，不属于除法单元格，也不影响坐标。

渲染器还读取 `textHorizontalAlign`（左、中、右）和 `textVerticalAlign`（上、中、下），以统一控制所有文本元素在各自区域或点位上的位置。文本盒保持内容自然宽度，不换行；在边或点位上，对齐值表示内容的延伸方向。页面默认方格宽度为 `30px`，字号比例默认 `1.00`，可在 `0.50–1.50` 间调整。

## 6. 同步与验证

主页面默认展示 SVG 网格，可通过“渲染模式”在 SVG 与 `div + CSS` 间切换。结果区右侧的数据流转模块依次展示 `DivisionComputation` 和当前的 `GridScene`，以便检查计算到渲染之间的数据。

修改以下内容时必须同步更新本文件：

- 轨道尺寸、列映射、行结构、小数点边中点、厂字弯、厂字横、边或辅助网格；
- `GridScene` / 元素位置契约；
- DOM 或 SVG 网格渲染方式。

完成后至少运行 `npm run test`、`npm run typecheck` 和 `npm run build`。厂字弯改动还必须确认 SVG 字符串、SVG DOM 和 DOM/CSS 三种输出均保持左下到右上，且端点与厂字横相接。

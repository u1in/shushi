# 加法竖式排版规则

> 版本：V3.0
> 适用范围：`AdditionComputation → 加法宏字符串 → compileMacro → GridScene → DOM / SVG` 的加法竖式

加法算法和过程字段见 [`加法计算规则.md`](../calculator/加法计算规则.md)。本文件只定义排版；渲染器不判断进位或加数。

## 1. 宏源码与行

加法布局器导出 `createAdditionMacroSource`，只填写 `GRID`、`ROW`、`CELL`、`RB` 与 `LINE` 等公开命令；`createAdditionGridScene` 仅兼容旧 API，内部直接调用 `compileMacro(source)`。用户复制源码后可在宏调试的宏源码框得到相同结果。

- 最左为宏中的一个完整运算符单元格，之后为数字列；所有加数、和都以个位右对齐。
- 数字列之间直接保留其真实公共边界；进位标记直接附着于既有单元格，不额外占用列轨道。
- 行顺序为：每个加数行、和行。连加时每个加数各占一行，`+` 仅放在最后一个加数行。
- `AdditionColumnStep.carryOut` 对应的进位与目标高位写在同一个 `CELL`，使用公开的 `RB(1)` 小号标记。成为最终和新最高位的进位已经出现在和中，不重复绘制提示。
- `showCarrySteps` 只影响进位文本元素；所有行列始终为真实的正尺寸轨道。

## 2. 横线与 token

横线由和行顶部的跨列 `edge` + `line` 元素绘制，并固定覆盖运算符列和数字区域；加法不提供横线范围开关。

| token                        | 用途                   |
| ---------------------------- | ---------------------- |
| `addition.addend`            | 加数                   |
| `addition.operator`          | 最后一行加数左侧的 `+` |
| `addition.carry`             | 行列交点上的小号进位   |
| `addition.sum-bar`           | 加法横线               |
| `addition.sum`               | 和                     |
| `addition.decimal-separator` | 输入与结果的小数点     |

`packages/web/src/styles/main.css` 只按 token 着色。DOM/CSS 和 SVG 共同消费同一份 `GridScene`，不得各自改变对齐、进位位置或横线范围。

## 3. 示例：356 + 278

```text
      1 1
      3 5 6
+     2 7 8
──────────
      6 3 4
```

进位 `1` 位于十位与个位、百位与十位的边界，并贴在加法横线之上；示意空格不是像素坐标。

## 3.1 小数点

加法计算器会先右补小数位并输出 `addendTexts` 与 `sumText`。完整竖式按共同小数位的边界放置数字：每个小数点通过同一个数字单元格中的 `DOT` 附着在整数个位右侧，不额外新增轨道；因此 `1.2 + 3.04 = 4.24` 的三个小数点垂直对齐。小数点使用 `addition.decimal-separator` token，进位仍按去点后的算术列定位。

播放从原始输入开始，补零前及补零中的每一帧均按当前可见数位右对齐，不预留最终结果或共同小数位的列。随后按加数书写顺序逐个补入右侧的 `0`；最后一个 `0` 出现时，小数点自然对齐。例如 `1.2 + 3.04` 先将 `1.2` 的末位与 `3.04` 的末位右对齐，下一帧显示 `1.20` 并与 `3.04` 的小数点对齐，之后才开始个位相加；整数 `5` 对齐到两位小数时依次显示 `5 → 5.0 → 5.00`。每补一个 `0` 都是独立帧，不把补零隐藏在首次计算帧中。

每一帧的数字区宽度取当前可见加数与已写和位的最大值；尚未产生的最高位进位和最终和不得提前扩展横线或网格。

当 `AdditionRenderSettings.useMinimalDecimalResult` 为 `true` 时，完整小数和的最后一个字符为 `0` 的结果行会在该 `0` 上附加 `STRIKE` 删除线，例如 `0.18 + 0.12` 的结果显示为 `0.30` 并划掉末位 `0`。该选项默认关闭，不改变 `sumText` 或播放步数；设置 `visibleStepCount` 时只有完成帧会显示删除线。

## 4. 步骤检查

`AdditionRenderSettings.visibleStepCount` 未设置时显示完整和；设置为 `k` 时先依次展示为对齐小数位补入的每个 `0`，之后才从个位开始显示 `resultDigit` 和对应进位。若输入含小数，全部数字列完成后会额外产生一个“补结果小数点”步骤：此前只显示去点的和，完成该步骤后才显示 `sumText` 的小数点。首页的“开始 / 上一步 / 下一步”只修改这个布局设置，用户可用“结束”恢复完整结果。

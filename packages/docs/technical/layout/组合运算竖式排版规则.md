# 组合运算竖式排版规则

组合布局不重算多个运算规则，而是将各单项布局器已生成的 `ROW` 与 `LINE` 连续放入**同一个** `GRID(...)` 宏源码。`createCompositeArithmeticMacroSource` 的返回值可直接复制到宏试验区，并由 `compileCalculatorMacro` 编译成一个 `GridScene`。

组合宏不携带当前网页专属的 `ariaLabel`，也会移除计算器页面内部的 `KV(style, ...)` 语义标记。自动配色会按行、运算符和进位宏重新推导，因此在默认格宽、行高、字号和关闭辅助网格时，首页“复制宏命令”经 `minifyMacro` 后会直接导出不含 `KV` 的顶层分号行最简源码。

首步保留完整的两个操作数行。自第二步起，布局器会移除该单项竖式原本的第一条 `ROW`：它对应的左操作数已经是紧邻上一段末行的结果，直接复用即可。例如 `125 + 75 - 20 × 3` 连续显示为 `125 / +75 / 200 / −20 / 180 / ×3 / 540`，不会重复写出 `200` 和 `180`。后续步骤为减法时，不会连同借位过程一并删除：布局器从被减数行提取 `MTD` 借位点，按右对齐列位置合并到复用的上一段结果行。因此 `500 + 1 - 237` 只写一行 `501`，该行仍显示减去 `237` 所需的借位点。

## 全局播放

`getCompositeArithmeticStepCount` 将各单项规则的教学事件数串接为一个全局长度。第一步直接进入自身的逐位过程；从第二步起，额外增加一个“引入第二操作数”事件：上一步最终结果完成时，下一段尚不显示；点击下一步后才显示运算符与第二操作数行，再点击才进入该段的逐位过程。`visibleStepCount` 由左至右分配，尚未到达的后续步骤不写入行。网页演示始终只渲染一个 `GridScene`，因此 DOM/CSS 和 SVG 仍只消费普通场景契约。

组合竖式工作区右侧与其他计算器一致，使用 `VisibleTextRowsPanel` 调用 `extractVisibleTextRows(scene)` 展示当前单一场景的 OCR 按行结果；它不从表达式字符串或计算器过程另行拼接文本。

## 配置

组合布局共享格宽、行高、字号和辅助网格，同时保留加法/乘法进位、减法借位及乘法横线配置。`showBorrowSteps` 默认关闭，以便连续竖式优先呈现每步结果；需要教学借位时传入 `true`。它不在布局层重算任何数字，也不在通用渲染器中新增组合运算分支。

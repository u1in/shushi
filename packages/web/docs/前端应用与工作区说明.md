# 四则运算竖式项目：多包工作区说明

> 适用范围：`@vertical-arithmetic/*` npm workspaces 的组织、依赖边界与本地开发

## 1. 包清单

| 包名 | 责任 | 公共 API |
| --- | --- | --- |
| `@vertical-arithmetic/grid` | 通用行列网格类型与轨道几何 | `GridScene`、`GridElement`、`resolveGridMetrics` 等 |
| `@vertical-arithmetic/calculators` | 加、减、乘、除、短除法等纯计算过程 | `computeAddition`、`computeSubtraction`、`computeDivision`、`computeMultiplication`、`computeShortDivision` 及计算结果类型 |
| `@vertical-arithmetic/layout` | 根据运算结果决定竖式结构并生成网格 | 五种 `create*GridScene` 函数及布局设置类型 |
| `@vertical-arithmetic/renderers` | 把网格渲染为 DOM/CSS 或 SVG | `renderDomGrid`、`renderSvgGrid` |
| `@vertical-arithmetic/macro-docs` | 网格宏文档的内容、页面组件、图例与样式 | `macroDocPages`、`MacroDocsLayout`、`MacroDocPage` 等 |
| `@vertical-arithmetic/web` | Vue Router 页面、命名图谱、Tailwind 主题和 Vite 前端应用 | 页面入口，不作为其他领域包的依赖 |

根工作区包名为 `@vertical-arithmetic/project`，所有包均为私有包，并由其 `package.json` 的 `workspaces: ["packages/*"]` 统一管理。包间依赖使用本地 `file:../<package>` 引用，以兼容本项目使用的 npm 版本；源码中一律使用 `@vertical-arithmetic/<package>` 作用域导入。

## 2. 依赖与数据流

```text
@vertical-arithmetic/calculators ──计算过程──┐
                                             ↓
@vertical-arithmetic/grid ←──── @vertical-arithmetic/layout
          ↑                                      ↓ GridScene
          └──── @vertical-arithmetic/renderers ──┘
                         ↑
                 @vertical-arithmetic/web
```

- `calculators` 与 `grid` 是底层纯 TypeScript 包，不能导入浏览器 API。
- `layout` 只根据计算结果和布局设置构建 `GridScene`，不创建 DOM 或 SVG。
- `renderers` 只读取 `GridScene`，不含除法、乘法、进位或借位等规则。
- `web` 负责 Vue 页面状态、Vue Router 路由和页面组件；`packages/web/index.html` 是唯一 Vite 应用壳，页面实现均位于该包。
- `macro-docs` 依赖 `macro`、`grid` 与 `renderers`，独立维护文档内容、图例与文档专用 SVG 预览；`web` 只负责挂载 `/macro-rules` 路由和提供站点外壳。

## 3. 新增代码的位置

- 新运算算法和结果类型：`packages/calculators/src/`；同时更新对应的中文计算规则文档。
- 新运算的布局引擎与布局设置：`packages/layout/src/`；同时更新对应的中文竖式排版规则文档。
- 共享网格契约或轨道几何：`packages/grid/src/`；同时更新 [`网格架构.md`](../../grid/docs/网格架构.md)。
- 通用 SVG / DOM/CSS 绘制能力：`packages/renderers/src/`；同时检查两个渲染器和通用架构文档。
- 页面交互、命名图谱或主题：`packages/web/src/`；需要新的页面时新增 Vue 路由页，不新增 HTML 入口。
- 网格宏文档内容、说明图例或文档交互：`packages/macro-docs/src/`；修改后运行文档测试并检查 `/macro-rules`。

首页网格宏试验区（`MacroPlayground`）的示例以紧凑源码维护在 `macroPlaygroundExamples.ts`，首次载入和切换示例时统一经 `formatMacro` 格式化为多行源码；工具栏仍提供“格式化 / 去格式化”手动切换；快速插入面板默认收起，可按需展开。测试会校验格式化前后的编译场景一致。

`GridPreview` 是首页计算器共享的画板宿主。它在 `division-stage` 相对定位容器内同时挂载 SVG 与 DOM/CSS 网格：该容器保证绝对定位图元以同一组 `GridScene` 尺寸为坐标系，SVG 节点保留 `division-svg` 样式类以复用语义 token 的字体、颜色和线条主题。修改这个宿主结构时，必须同时检查两种渲染模式。

每个首页计算器都通过 `StepPlaybackControls` 独立检查自己的过程；“开始 / 上一步 / 下一步”改变布局设置中的 `visibleStepCount`，“结束”恢复未设置游标的完整场景。控制器不重算、不修改计算器过程 JSON，只请求布局层重新生成当前步骤的 `GridScene`。

首页每个运算板块的 OCR 按行结果由 `VisibleTextRowsPanel` 作为独立的第三列面板显示在计算结果右侧；宽屏保持最右侧，窄屏自动落到工作区下一行。面板默认展开并在场景更新时实时刷新，按钮可收起或重新展开 JSON 输出。

各运算元素命名图谱使用 `NamingMapGrid` 展示语义高亮，并在运算器结果下方通过 `RendererDataPanel` 展示布局层实际传给渲染器的 `GridScene` 数据及字段注释。该面板只读展示渲染输入，不修改场景或渲染结果。

## 4. 开发与验证

在 WSL 中先加载 fnm 环境，然后从仓库根目录运行：

```bash
source ~/.zshrc
npm install
npm run typecheck
npm run test
npm run build
```

根目录的 `dev`、`typecheck`、`test`、`build` 脚本都会进入 `packages/web` 执行；其中 `typecheck` 使用 `vue-tsc`，`build` 使用该包的 Vite 配置和唯一的 `index.html` 应用壳。不要在某个子包内单独复制锁文件。

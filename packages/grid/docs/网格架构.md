# 四则运算竖式项目：网格架构与子包关系

> 版本：V2.3
> 适用范围：项目级的计算器、布局引擎、行列网格、渲染器与规则文档约定

## 1. 项目目标

本项目用于展示四则运算和短除法的计算过程与竖式。已实现加、减、乘、除和短除法器；每种运算均复用通用行列网格和渲染器，但保留独立的计算规则与布局规则。

## 2. 统一分层

```text
<Operation>Computation
        ↓
create<Operation>GridScene（layout）
        ↓
GridScene（grid）
        ↓
SVG renderer / DOM + CSS renderer
```

- **计算层**：验证输入，执行运算，输出可检查的过程数据与语义 token。禁止输出像素、DOM、CSS 或渲染器专属数据。
- **布局引擎层**：联合计算结果、布局设置和网格模型，决定某一运算的竖式结构并生成 `GridScene`。商、进位、借位、部分被减数、部分减数、部分积等都属于此层的运算布局规则。
- **通用网格层**：用可变尺寸轨道和 `GridElement` 描述行列结构与预定义位置，不理解具体运算；该层是布局引擎与渲染器共同使用的网格核心。
- **渲染层**：SVG 与 DOM/CSS 只根据 `GridScene` 画出轨道、文本、边框、圆角与调试网格。

## 3. `GridScene` 契约

`GridScene` 包含：

- `columns` / `rows`：以单位宽高定义的可变轨道；每个尺寸必须为正有限数，只描述真实可见的行列；
- `padding`、`unitWidth`、`unitHeight`、`fontSize`：场景尺寸与默认字体配置；
- `elements`：可带文本、直线、圆角的绘制元素；位置可为单元区域、行列交点、单元格边或边中点，文本可选 `fontSizeRatio` 与跨 DOM/SVG 共用的 `color` 覆盖值；直线和圆角均可选通用 `color` 与正数 `thickness` 覆盖值；
- `textHorizontalAlign` / `textVerticalAlign`：场景级全局文本对齐；
- `showGuideGrid`：全轨道辅助网格；
- `ariaLabel`：场景级无障碍说明。

文本单元格可以在 `content.horizontalAlign` / `content.verticalAlign` 提供局部覆盖值。解析优先级为：**单元格覆盖 → 场景全局配置 → 渲染器基础样式**。

### 3.1 可见文本行 API（OCR 对照）

`@vertical-arithmetic/grid` 公开 `extractVisibleTextRows(scene: GridScene): string[]`。它只读取布局层已生成的 `GridScene`，按实际绘制锚点从上到下、从左到右合并所有非空 `text` 元素；直线、厂字弯和空白轨道不会出现在结果中。

```ts
const rows = extractVisibleTextRows(scene)
// 例如带进位的 356 + 278：['356', '+278', '11', '634']
```

它特意不输出列坐标，适合 OCR 已按书写行识别、但横向位置不稳定的比对。API 与 DOM/SVG 渲染器共享文本锚点规则：元素级 `horizontalAlign` / `verticalAlign` 优先于场景默认值。因此普通格内数字、左右边中点文本（例如小数点）会与同一视觉行合并，而交点、上下边界及 `RB`/`MT` 等局部定位的进位、借位提示会单独形成注记行，不会与操作数或结果混在同一字符串。相同高度的文本按横向锚点排序，完全重合时保持 `elements` 声明顺序。该 API 不辨认具体运算，因而适用于所有布局器和宏生成的网格。

### 3.2 预定义位置与元素锚定

- `GridTrack.size` 必须是正有限数；网格没有零宽列或零高行。轨道可使用小数单位，例如短除法以连续的 `0.5u` 列轨道表达半格阶梯；布局层可让 `cell` 通过 `columnSpan` 合并相邻轨道，作为一个 `1u` 数字单元格。几何层和两种渲染器只解析合并后的区域，不理解“半格”所属的运算语义。
- `GridElement.position` 是可判别联合：`cell` 表示一个或多个完整单元格区域；`intersection` 表示列边界与行边界的交点；`edge` 表示完整单元格边；`edgeMidpoint` 表示该边中点。横线、竖线、小数点、进位和借位提示都使用这些天然存在的位置，而不再伪造轨道。宏语言的 `RBL` / `DOT` 当前降级为右侧 `edgeMidpoint` 文本，并使用与普通格内文本相同的行框对齐。
- 文本按“位置矩形 / 点 + 自然尺寸盒”放置：区域沿其范围对齐；边可用于边上的文本或 `line`；交点和边中点是零面积点，`center` 骑点居中，其他对齐值决定文字延伸方向。结构图元必须显式设置局部对齐，避免受页面全局对齐控件影响。
- Web 渲染主题中的 `line` 元素使用 2px 整数像素线宽；DOM/CSS 使用无圆角矩形，SVG 使用 `butt` 线帽，避免圆角端点和半像素定位造成边缘模糊。
- 文本、直线、圆角的内容级 `color` / `thickness` 是渲染器无关的最终视觉覆盖，优先于 `styleToken` 对应的页面 CSS。`@vertical-arithmetic/macro` 的 `GRID(autoColor)` 使用该能力输出 40 行固定调色板；通用网格层不理解“进位、借位或运算符”的语义。
- 内容墨迹必须留在网格矩形内：SVG 的 `viewBox` 和 DOM 的滚动 / 裁切祖先都会裁掉网格外的内容。需要向网格外延伸时，由排版层通过 `padding` 预留空间。
- 绘制顺序：线与圆角层始终在文本层之下；同一层内按 `elements` 数组顺序绘制。内容重叠时，后出现的元素压住先出现的元素。

布局引擎共同接收 `GridRenderSettings`（方格宽度、行高、字号比例、辅助网格和默认文本对齐）。运算专属设置不得反向进入其他运算的计算层；例如除法的厂字弯、减法线和零商步骤设置属于 `RenderSettings`，乘法的横线等宽与进位显示设置属于 `MultiplicationRenderSettings`。

`GridRenderSettings.visibleStepCount` 是可选的教学检查游标，由布局层解释而不是由通用渲染器解释。未设置时渲染完整计算结果；设置为非负整数时，各运算布局按自己的过程语义截取 `GridScene`。主页上的每个计算器独立维护该游标，并通过“开始 / 上一步 / 下一步 / 结束”反复检查，不改变计算层返回的过程数据。

### 3.3 网格文本字体

整个网站统一使用 Computer Modern 相关的数学衬线字体栈（`Computer Modern` → `CMU Serif` → `Latin Modern Roman` → `Latin Modern Math` → `STIX Two Math` → `Cambria Math` → `math` → `Times New Roman` → `Noto Serif SC` → `serif`），包括页面 UI、网格文本、输入数字、结果标题、计算摘要、参数输出、JSON 数据和命名图谱。数字保持 `tabular-nums`，保证列宽和错位对齐。字体按系统已安装情况从左到右回退，`Computer Modern`、`CMU Serif` 与 `Latin Modern` 均属于 Computer Modern 字体体系或其兼容衍生字体。

## 4. 多包工作区与数据流

项目使用 npm workspaces，并统一采用 `@vertical-arithmetic/*` 作用域。根目录只负责工作区编排；Vite、Vue 前端应用和对外 HTML 均位于 `packages/web/`。

| 包 | 源码位置 | 职责 | 可以依赖 |
| --- | --- | --- | --- |
| `@vertical-arithmetic/grid` | `packages/grid/src/` | `GridScene` 网格契约、轨道解析和几何工具 | 无 |
| `@vertical-arithmetic/calculators` | `packages/calculators/src/` | 各运算的输入校验、算法和过程结果契约 | 无 |
| `@vertical-arithmetic/layout` | `packages/layout/src/` | 联合计算结果与网格模型，决定竖式结构并生成 `GridScene` | `grid`、`calculators` |
| `@vertical-arithmetic/macro` | `packages/macro/src/` | 解析人类可写宏、推导通用行列结构并生成 `GridScene` | `grid` |
| `@vertical-arithmetic/renderers` | `packages/renderers/src/` | 只消费 `GridScene` 的 SVG 与 DOM/CSS 渲染器 | `grid` |
| `@vertical-arithmetic/web` | `packages/web/src/` | Vue 页面、路由、组件、Tailwind 主题与浏览器集成 | 上述四个包 |

当前架构的数据流是：

```text
calculators
    │  输出 OperationComputation
    ▼
layout / macro
    │  按运算规则编排 GridScene
    ▼
grid
    │  提供 GridScene、轨道解析和几何计算
    ▼
renderers
    │  输出 DOM/CSS 或 SVG
    ▼
web
```

其中 `layout` 是运算专属的决定性处理层；`macro` 则是人类可写公式的通用编译层，两者都只能输出 `GridScene`。`grid` 不负责决定除法或乘法的行列规则，只提供所有布局引擎、宏编译器和渲染器共享的网格模型与几何工具。依赖方向必须单向，不得让计算器依赖布局、网格或浏览器 API，也不得让渲染器依赖运算器。

`packages/web/index.html` 是唯一的 Vite 应用壳，只挂载 Vue 入口。具体页面由 Vue Router 的 `HomePage` 和各运算命名图谱页在 `/`、`/addition-elements`、`/subtraction-elements`、`/division-elements`、`/multiplication-elements`、`/short-division-elements` 路由提供，页面布局使用 Tailwind CSS，网格高亮由共享的 `NamingMapGrid` 组件提供。根目录的 `npm run dev`、`npm run build` 等脚本会先进入该包执行前端命令。

各内部包通过其 `src/index.ts` 提供公共 API。跨包代码必须使用 `@vertical-arithmetic/<package>` 导入，不能回退为 `../../` 跨目录深层导入。

主页由 `HomePage.vue` 组合每种运算的 Vue 计算器组件；新增运算器应新增独立组件并在该页面组合，而不是把不同运算的响应式状态混在同一个组件中。每个计算器通过 `StepPlaybackControls` 独立维护步骤游标，使用“开始 / 上一步 / 下一步”检查过程，并通过“结束”恢复完整结果。计算器通过 `GridPreview` 在 SVG、DOM/CSS 或两者模式下渲染同一份 `GridScene`。命名图谱页面通过 `NamingMapGrid` 从真实单元格和边线计算高亮框，并通过 `RendererDataPanel` 展示实际交给渲染器的 `GridScene` JSON 与字段注释；筛选只改变 Vue 管理的高亮可见状态，不得修改计算结果、`GridScene` 或渲染器输入。

## 5. 新运算器接入清单

每新增一种运算器，至少完成：

1. 在 `@vertical-arithmetic/calculators` 新建计算模块，例如 `packages/calculators/src/addition.ts`，并定义 `<Operation>Computation`；
2. 在计算器包中新建该运算规则文档，例如 `packages/calculators/docs/加法计算规则.md`；
3. 在 `@vertical-arithmetic/layout` 新建布局引擎模块，例如 `packages/layout/src/addition-layout.ts`；
4. 在布局包中新建或扩展中文命名的专项布局文档，例如 `packages/layout/docs/加法竖式排版规则.md`；
5. 为计算规则、布局映射、异常输入和关键边界条件添加测试；
6. 仅通过 `grid` 提供的 `GridScene` 连接既有 SVG / DOM 渲染器；
7. 如提供图谱，记录可见物件、线框边界与 JSON 字段说明。

不要为了“统一”而把不同运算的算法、过程对象或行列规则压缩为一个除法风格的数据结构。

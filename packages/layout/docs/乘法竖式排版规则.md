# 乘法竖式与通用网格排版规则

> 版本：V1.4<br>
> 适用范围：四则运算竖式项目中乘法器的竖式坐标、网格场景、DOM/CSS 与 SVG 对照渲染

整数逐位乘法和过程数据见 [`乘法计算规则.md`](../../calculators/docs/乘法计算规则.md)。本文件只定义 `MultiplicationComputation` 如何编排为通用网格，不在渲染器中实现乘法规则。交互式元素命名图谱见 [`../../web/src/pages/MultiplicationNamingMapPage.vue`](../../web/src/pages/MultiplicationNamingMapPage.vue)。

## 1. 分层与职责

```text
MultiplicationComputation → createMultiplicationGridScene → GridScene → DOM / SVG renderer
```

- `packages/calculators/src/multiplication.ts` 输出字符串数字、逐位进位、部分积、十进制位移和按列求和过程。
- `packages/layout/src/multiplication-layout.ts` 读取这些过程数据，处理右对齐、部分积错位、可见进位和两条横线。
- `GridScene` 仍是完全通用的可变轨道场景，不理解被乘数、部分积或进位。
- `packages/renderers/src/dom-grid-renderer.ts` 与 `packages/renderers/src/svg-grid-renderer.ts` 只消费 `GridScene`；它们不得判断乘数位或重新计算进位。

## 2. 网格轨道与对齐

普通数字列宽为 `1u`，其中 `u = cellWidth`。最左另设 `0.72u` 的运算符列，乘号 `×` 位于该列的乘数行。数字区域的列数取被乘数、乘数、部分积（含 `shift`）和最终积所需宽度的最大值。相邻数字列之间**无条件预创建**一条 `0u` 的进位锚线列（`carry-boundary-*`）：它不占宽度，只给进位标记提供“来源列与目标列之间”的落点；当前没有进位时该轨道仍然存在，以保证结构稳定。

- 被乘数、乘数和最终积的最后一位均与数字区域最右列对齐。
- 布局层接收的 `multiplicandDigits` 已经由计算层规范化为较大操作数，始终放在第一行；`multiplierDigits` 为较小操作数，始终放在第二行。
- 一个部分积的最后一位对齐到 `数字区域最右列 - shift`；因此个位部分积右对齐，十位部分积左移一格，百位部分积左移两格。
- 数字区域列数先由布局层完整计算。渲染器不能为对齐目的测量 DOM 或修改轨道。

## 3. 行结构

```text
Row 0：被乘数
Row 1：× 乘数
零高 Row：乘法横线
重复：零高 Row：本位进位（预创建，可能为空）→ Row：部分积
零高 Row：部分积相加时的进位（预创建，可能为空；仅多位乘数）
零高 Row：求和横线
最后 Row：最终积
```

- 只有一个乘数位时，唯一的部分积就是最终积，不重复绘制一行，也没有求和横线。
- 乘数有多位时，所有部分积（包括值为 `0` 的部分积）依 `shift` 绘制；最后一条部分积下方绘制求和横线，下一行绘制最终积。
- 乘法横线始终位于乘数行之后的独立 `0h` 行，求和横线位于最终部分积之后的独立 `0h` 行。横线不再挂在进位行的底边，因此有无进位都不会移动横线；`showCarrySteps` 关闭时网格高度也不变。
- 每条部分积上方都预创建一条 `0h` 的进位行；当该部分积中存在 `digitSteps.carryOut > 0` 且对应的 `multiplicandDigitIndex > 0` 时，把进位文本写进目标数字列与其右侧来源数字列之间的 `0u` 进位锚线列。进位文本同时使用 `horizontalAlign: "center"` 和 `verticalAlign: "bottom"`：水平方向骑在两列边界上，垂直方向从行边界向上延伸，占用上一行下半部的留白；它不消耗额外行高，也不压进目标列的格心。没有进位的部分积保留空的 `0h` 行。
- 后续部分积的进位同样写进各自预创建的行与列；这不会改变乘法横线的位置。
- 多位乘数在最终部分积和求和横线之间**无条件预创建**一条 `0h` 的加法进位行；当存在 `additionSteps.carryOut > 0` 时，把进位写进目标列与来源列之间的 `0u` 进位锚线列并水平居中。最高位相加产生的进位既进入最终积的最高位，也会在求和横线上显示，用来解释最高位是如何形成的。
- 零高行之间共享同一条边界：乘法横线 / 求和横线的 y 由相邻内容行的边界决定，进位在线的哪一侧由 `verticalAlign` 决定。默认向上，也就是略高于横线、压入上一行的下缘留白。没有任何内容的预创建零高行不改变任何坐标。
- 0 宽进位列与左右数字列共享边界：`horizontalAlign: "center"` 时，进位字形以该边界为中心左右展开，因此落在两列之间而不是任一列的格心。
- `showCarrySteps` 只控制进位文本单元格：关闭时逐位乘法进位和加法进位不再写入文本，但预创建的零高进位行和 `0u` 进位锚线列仍然保留；计算层的 `digitSteps` 与 `additionSteps` 不受影响。
- 进位文本使用 `fontSizeRatio: 0.42`，即按 `GridScene.fontSize` 缩小为教学标记。该属性是通用文本单元格能力，DOM/CSS 与 SVG 渲染器以相同方式处理，不包含任何乘法专属判断。
- 进位向上延伸会占用上一行下缘的留白。它水平位于两列之间，默认不会压住数字；但 `fontSizeRatio` 很大或行高很小时，进位仍可能侵入相邻数字的横向空间。这是该排版技巧的预期取舍，需要在极端参数下目检。
- 进位只显示在它还将参与下一高位计算的位置；最左位最后一步产生的进位只作为部分积新增的最高位，不绘制独立进位符号。
- 乘法横线覆盖运算符列和全部数字区域；求和横线覆盖数字区域。两条横线都由跨列空 `GridCell` 的 `bottom` 边绘制，而不是由渲染器创建独立线段。横线单元格的 `columnSpan` 按轨道数计数，因此包含夹在数字列之间的 `0u` 进位列；这些轨道宽度为 0，横线的像素长度不变。
- `uniformMultiplicationBars` 开启时，求和横线扩展到运算符列，使它与乘法横线同起点、同终点、同宽；关闭时保留默认教学排版，即乘法横线含运算符列、求和横线只覆盖数字区域。

## 4. `GridCell` 与语义样式

文本均使用 `GridCell.content.kind = "text"`；横线使用 `GridCell.edges.bottom = true`。乘法专用 token 由布局层填写：

| token | 用途 |
| --- | --- |
| `multiplication.multiplicand` | 被乘数 |
| `multiplication.multiplier` | 乘数 |
| `multiplication.operator` | 乘号 `×` |
| `multiplication.carry` | 逐位乘法零宽进位列、零高进位行中的小号进位提示（水平居中、向上延伸） |
| `multiplication.addition-carry` | 部分积相加时的小号进位提示（水平居中、向上延伸） |
| `multiplication.partial-product` | 多位乘数产生的部分积 |
| `multiplication.product` | 最终积；一位乘数时也承载唯一部分积 |
| `multiplication.input-bar` | 乘数行下的乘法横线 |
| `multiplication.sum-bar` | 多位乘数的部分积求和横线 |

`packages/web/src/styles/main.css` 只按上述 token 着色；DOM/CSS 与 SVG 均复用相同 token。文本的水平/垂直对齐未在单元格覆盖时，继承 `GridScene.textHorizontalAlign` 与 `GridScene.textVerticalAlign`。`showGuideGrid` 覆盖所有已解析轨道，用于检查错位，不属于乘法计算过程。

## 5. 示例：145 × 12

计算层导出：

```text
部分积 290，shift 0（5 × 2 时向十位进 1）
部分积 145，shift 1
最终积 1740
```

布局得到的阅读结构为：

```text
      145
×      12
─────────
      290
     145
─────────
     1740
```

进位、部分积和最终积的精确列均由 `shift` 和 `digitSteps` 推导；示意中的空格不表示像素坐标。首个部分积的进位 `1` 绘制在乘法横线上方，落在乘数 `12` 的十位与个位之间的零宽锚线列上；它与横线共享边界，不额外占用行高，上图省略了这条进位标记。

## 6. 同步与验证

修改列宽、进位锚线列、行结构、错位、进位（含 0 宽列、0 高行与向上延伸方向）、横线、token、`GridScene` 或任一渲染器时，必须同步更新本文件；同时检查 [`网格架构.md`](../../grid/docs/网格架构.md) 是否需要反映共享契约变化。

完成后至少运行：

```bash
source ~/.zshrc
npm run typecheck
npm run test
npm run build
```

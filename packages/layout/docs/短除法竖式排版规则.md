# 短除法竖式排版规则

> 适用范围：`createShortDivisionGridScene` 将 `ShortDivisionComputation` 转换为通用 `GridScene` 的轨道、行列和语义样式。计算终止条件见 [`短除法计算规则.md`](../../calculators/docs/短除法计算规则.md)。

## 1. 职责边界

短除法布局只读取计算器的 `inputValues`、`steps` 和 `finalValues`。分解质因数、公因数、进制转换的算法差异只在计算器中表达；布局不决定试除质数、GCD / LCM 或余数倒序。DOM/CSS 和 SVG 渲染器均只消费本层输出的 `GridScene`。

## 2. 轨道与行结构

```text
左除数列 | 竖线 | 右侧数值组 [余数标签 余数]
          ────────────────────────────  每轮横线
            下一轮商
```

- 左侧除数列宽为 `1.1u`；右侧每个数字格前均预建一条 `0u` 锚线轨道。竖线使用本轮首个右侧数字前的锚线，因此它贴住该数字的左边框，且不会产生任何额外宽度。右侧每组数字为 `1u` 数字轨道，多输入数之间保留 `0.34u` 空隙。
- 数值组的宽度取全部输入、过程数、商和底行中该组最大位数，用来确定右边界；每行数字在组内保持**右对齐**。例如 `2｜12` 的下一行 `2｜6` 中，`6` 仍位于 `2` 的正下方，但该行竖线移动到 `6` 的左边框。
- 每条 `steps` 对应一个内容行和紧随其后的 `0h` 横线锚行；`finalValues` 另占底行且不画横线。
- 每个 `short-division.separator` 是本轮内容行的 `0u` 锚线轨道上的 `left` edge；`short-division.divisor` 也按本轮锚点定位，始终渲染在竖线左侧紧邻的一个数字格中，不能固定在最左列。底行不画竖线。`short-division.bar` 从数值区统一的最右边界向左延伸至**本轮**竖线锚线。因此当位数变少时，数字保持右对齐，除数、竖线和横线左端会一起右移。
- `short-division.separator` 与 `short-division.bar` 在 SVG 和 DOM/CSS 中均使用 `2px`、直角、无圆角端点的硬朗线条；它们与加、减、乘、除竖式的横线和除法厂字线保持相同的粗细与端点表现。
- 仅进制转换且 `showRemainders` 为真时，在右侧附加“余”和余数字段；它不改变右侧商的列对齐。

质数分解的最后质数、公因数模式的互质底行以及进制转换的 0 底行，都使用相同的 `short-division.final` 语义 token，因此无须让渲染器理解三种终止条件。

## 3. 语义样式 token

| token | 图元 |
| --- | --- |
| `short-division.divisor` | 左侧质数、公共质数或目标进制 |
| `short-division.separator` | 短除竖线 |
| `short-division.dividend` | 每轮右侧原数 / 当前商 |
| `short-division.bar` | 通向下一行商的横线 |
| `short-division.remainder-label` / `.remainder` | 进制转换的“余”和余数 |
| `short-division.final` | 停止时的底行值 |

页面主题为上述 token 提供颜色；通用渲染器无需新增运算条件。辅助网格来自 `GridScene.showGuideGrid`，覆盖所有解析后的轨道而不影响坐标。

## 4. 页面与图谱

`ShortDivisionCalculator.vue` 提供三种模式、输入、方格尺寸和余数开关；`ShortDivisionNamingMapPage.vue` 用真实的 13 转二进制场景标出全部可见图元。修改轨道、边线或 token 时，必须同步更新该图谱和本文档，并验证 SVG 与 DOM/CSS 两种输出。

# 加法竖式排版规则

> 版本：V1.0  
> 适用范围：`AdditionComputation → GridScene → DOM / SVG` 的加法竖式

加法算法和过程字段见 [`加法计算规则.md`](../../calculators/docs/加法计算规则.md)。本文件只定义排版；渲染器不判断进位或加数。

## 1. 轨道和行

- 最左为 `0.72u` 的运算符列，之后为数字列；所有加数、和都以个位右对齐。
- 相邻数字列间无条件建立 `0u` 的 `carry-boundary-*` 进位锚线列，保证有无进位时结构稳定。
- 行顺序为：每个加数行、零高进位行、零高加法横线行、和行。连加时每个加数各占一行，`+` 仅放在最后一个加数行。
- 进位行和加法横线行均为 `0h`，共享最后一个加数行与和行之间的同一条边界。`AdditionColumnStep.carryOut` 对应的进位写在目标高位与来源低位之间的零宽列，使用 `fontSizeRatio: 0.42`、居中和向上对齐，故视觉上落在**加法横线之上**。成为最终和新最高位的进位已经出现在和中，不重复绘制提示。
- `showCarrySteps` 只影响文本单元格；预创建的零宽列和零高行始终保留。

## 2. 横线与 token

横线由独立零高行中的跨列 `GridCell.edges.bottom` 绘制，并固定覆盖运算符列和数字区域；加法不提供横线范围开关。

| token | 用途 |
| --- | --- |
| `addition.addend` | 加数 |
| `addition.operator` | 最后一行加数左侧的 `+` |
| `addition.carry` | 零宽 / 零高锚线上的小号进位 |
| `addition.sum-bar` | 加法横线 |
| `addition.sum` | 和 |

`packages/web/src/styles/main.css` 只按 token 着色。DOM/CSS 和 SVG 共同消费同一份 `GridScene`，不得各自改变对齐、进位位置或横线范围。

## 3. 示例：356 + 278

```text
      1 1
      3 5 6
+     2 7 8
──────────
      6 3 4
```

进位 `1` 位于十位与个位、百位与十位的边界，并贴在加法横线之上；示意空格不是像素坐标。

# 小学除法竖式与通用棋盘排版规则

> 版本：V18.0
> 适用范围：小学竖式项目中除法器的竖式坐标、棋盘场景、DOM/CSS 与 SVG 对照渲染

整数逐位长除法规则和计算过程见 [`除法计算规则.md`](./除法计算规则.md)。本文件定义除法如何把计算过程编排为通用棋盘，不在渲染器中保留除法规则。

## 1. 分层与职责

```text
DivisionComputation → createDivisionBoardScene → BoardScene → DOM / SVG renderer
```

- `src/calculators/division.ts` 只产出字符串计算过程和语义商 token，不包含像素、行号或 DOM 信息。
- `src/layouts/division-layout.ts` 只负责除法排版：可见步骤、对齐、厂字弯、小数点轨道和减法线。
- `BoardScene` 是通用渲染契约，由 `columns`、`rows`、`cells`、边距和默认字体配置组成。
- `src/renderers/dom-board-renderer.ts` 与 `src/renderers/svg-board-renderer.ts` 只消费 `BoardScene`；它们不能判断什么是商、部分被减数或零商步骤。

## 2. 棋盘轨道与单元格

棋盘使用可变宽列和可变高行。普通数字列宽为 `1u`，普通行高为 `1h`，其中 `u = cellWidth`、`h = rowHeight`。

| 轨道 | 尺寸 | 用途 |
| --- | --- | --- |
| 数字列 | `1u` | 除数、被除数、商、乘积、余数和补零 |
| 厂字弯列 | `0.5u` | 除数和被除数之间的厂字弯单元格 |
| 小数分隔列 | `0.34u` | 有限小数时，原被除数末列与首个补零列之间的窄列 |
| 行 | `1h` | 商、被除数、过程和余数行 |

`BoardCell` 是唯一的可绘制图元。单元格可承载：

- `text`：数字、符号或小数点；文本可设置自己的 `styleToken`，没有 token 时继承渲染器默认文本样式；
- `corner`：厂字弯等圆角边框；
- `edges`：任意边框。减法线和顶部横线均为跨列空单元格的边框，而不是独立线段。

单元格可以通过其所在轨道类型提出尺寸要求；轨道尺寸必须由排版层在渲染前确定。渲染器只能读取已完成的 `BoardScene`，不得在 DOM 测量后修改行高或列宽。

## 3. 除法坐标映射

计算列和显示列必须分离：

- `dividendColumn` 仅指被除数或补零的逻辑列。
- 每个 `quotientTokens` 项均提供独立的显示 `column`；小数点作为 `{ kind: "decimalSeparator", digit: "." }` 占据自己的列，而不使用“前一列之后”的边界描述。
- 排版层把逻辑列和 token 显示列映射至棋盘轨道，成功得到有限小数时在原被除数最后一列后插入小数分隔窄列。
- 因此小数点、补零、后续商位和部分被减数都能在棋盘中对齐，同时不会污染逐位除法逻辑。

## 4. 行结构与除法单元格

```text
Row 0：商数字及（如有）小数点单元格
Row 1：除数、厂字弯单元格、被除数；被除数区域的顶部边框
Row 2：首轮部分减数（乘积）；单元格底边为减法线
后续步骤：部分被减数 → 部分减数；部分减数单元格底边为减法线
最后一行：最终余数（包括 0）
```

- 除数按数字单元格右对齐，最右格紧接 `0.5u` 的厂字弯列。
- 被除数、商、部分被减数、部分减数和余数都按逻辑被除数列对齐；多位数右对齐到本轮 `dividendColumn`。
- 首轮部分被减数已在被除数行出现，只绘制首轮部分减数和减法线。
- 厂字弯是一个 `corner` 单元格，方向固定为左下到右上，并使用固定的标准圆角比例；它不提供页面调节控件。
- 厂字横和减法线是单元格边框，线宽为 `3px`；减法线右端固定于最后一个数字列的右边界。
- “减法横线等宽”开启时，所有减法线使用所有可见步骤中最靠左的逻辑起始列。
- 试商为 `0` 的步骤始终存在于计算输出；“显示试商为 0 的步骤”关闭时，排版层过滤其过程单元格并重新计算行数和总高度。

## 5. 小数与样式

`quotientTokens` 中的小数分隔符是语义 token。排版层为其创建文本为 `.` 的单元格，并放进独立的 `0.34u` 小数分隔列。它不再是附着于数字列边界的像素标记。

单元格外框/边线使用 `BoardCell.styleToken`，文本使用 `BoardTextContent.styleToken`。例如除数文本使用 `division.divisor`，减法线单元格使用 `division.subtraction-bar`。没有指定 token 的文本继承 `BoardScene.defaultTextStyleToken` 的渲染配置；未配置该默认 token 时才回退到渲染器的基础颜色和字重。文本的 `horizontalAlign` / `verticalAlign` 可在单元格内单独覆盖；没有覆盖值时分别继承 `BoardScene.textHorizontalAlign` / `textVerticalAlign`。这允许未来的加法、乘法共享渲染器并各自定义教学样式。

辅助网格是 `BoardScene.showGuideGrid` 对应的渲染器调试能力。它覆盖所有已解析轨道，不属于除法单元格，也不影响坐标。

渲染器还读取 `textHorizontalAlign`（左、中、右）和 `textVerticalAlign`（上、中、下），以统一控制所有文本单元格在各自边界内的位置。页面默认方格宽度为 `30px`，字号比例默认 `1.00`，可在 `0.50–1.50` 间调整。

## 6. 同步与验证

主页面默认展示 SVG 棋盘，可通过“渲染模式”在 SVG 与 `div + CSS` 间切换。结果区右侧的数据流转模块依次展示 `DivisionComputation` 和当前的 `BoardScene`，以便检查计算到渲染之间的数据。

修改以下内容时必须同步更新本文件：

- 轨道尺寸、列映射、行结构、小数分隔列、厂字弯、厂字横、边框或辅助网格；
- `BoardScene` / 单元格契约；
- DOM 或 SVG 棋盘渲染方式。

完成后至少运行 `npm run test`、`npm run typecheck` 和 `npm run build`。厂字弯改动还必须确认两个渲染器均保持左下到右上，且端点与厂字横相接。

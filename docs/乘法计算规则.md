# 小学乘法计算规则

> 版本：V1.0  
> 适用范围：小学竖式项目的非负整数乘法器、逐位过程和渲染数据流

本文件定义 `src/calculators/multiplication.ts` 的计算行为。乘法竖式如何映射到可变轨道棋盘见 [`乘法竖式排版规则.md`](./乘法竖式排版规则.md)。

## 1. 术语与输入约束

| 术语 | 代码名称 | 约束 |
| --- | --- | --- |
| 被乘数 | `multiplicandDigits` / `a` | 非负整数 |
| 乘数 | `multiplierDigits` / `b` | 非负整数 |
| 部分积 | `partialProducts` | 乘数每一位对应的一行未错位数字及其位移 |
| 积 | `productDigits` / `p` | 非负整数 |

- 只接收十进制非负整数字符串；空值、小数、负数、空白或其他格式必须报错，不得静默转换。
- 输入前导 `0` 在计算前移除，零规范化为字符串 `"0"`。
- 整段数字、部分积和最终积均用字符串保存，不得把整段数字转换为 `Number`、`BigInt` 或其他大数类型。
- 单个数字字符以及单列合计可暂时转为 `Number`，仅用于一位乘法、进位和一列求和。

## 2. 核心不变量

任意完整计算必须满足：

```text
p = a × b
```

其中每个部分积 `partialProducts[i]` 满足：

```text
partialProducts[i].value × 10 ^ partialProducts[i].shift
  = a × 当前乘数位的数值 × 10 ^ shift
```

`shift` 从乘数个位算起：个位为 `0`、十位为 `1`、百位为 `2`。最终积由所有带位移的部分积按列相加得到，故不受 JavaScript 安全整数范围限制。

## 3. 操作数顺序规范化

竖式固定遵循“大数在第一行，小数在第二行”的规则：

- 输入的两个规范化数字中，位数较长者作为 `multiplicandDigits`，写在第一行；位数较短者作为 `multiplierDigits`，写在第二行。
- 位数相同时按字典序比较，数值较大者在第一行；两个数相等时保持输入顺序。
- 交换只改变竖式展示和逐位计算的顺序，不改变乘积；`operandsSwapped` 记录是否发生过交换。
- 该规范化在计算层完成，布局层不重新比较数字，渲染器只消费已经确定的 `BoardScene`。

## 4. 逐位乘法

乘数从右向左遍历。对每个乘数位，令 `carry = 0`，被乘数从右向左逐位计算：

```text
total      = 当前被乘数位 × 当前乘数位 + carry
resultDigit = total % 10
carry       = floor(total / 10)
```

- `resultDigit` 从右向左写入该部分积。
- 最后一位后若 `carry > 0`，将它写到部分积左侧。
- 如果这是被乘数最左位的最后一步，产生的 `carry` 只写入部分积左侧作为最高位，不再额外绘制进位符号；只有还会传给下一位乘法的进位才属于可见进位标记。
- 每次逐位计算都记录 `MultiplicationDigitStep`：被乘数位索引、两个数字、进位输入、`total`、写下的数字和进位输出。
- `digitSteps` 按被乘数从左到右的阅读顺序导出；每步的 `carryOut` 是其右侧相邻位传入该步的进位，最左一步的 `carryOut` 是部分积新增的最高位。

## 5. 部分积错位与按列相加

每一个乘数位都生成一个 `MultiplicationPartialProduct`：

| 字段 | 含义 |
| --- | --- |
| `multiplierDigitIndex` | 当前乘数位在规范化乘数字符串中的左起零基索引 |
| `multiplierDigit` | 当前参与逐位乘法的数字字符 |
| `shift` | 当前位从右起的位置；只表达十进制错位，不包含棋盘坐标 |
| `value` | 不补位、不含位移的部分积数字字符串 |
| `digitSteps` | 该部分积的逐位乘法与进位过程 |

计算器再从所有部分积的最右列向左列加：

```text
total       = 所有对齐部分积的当前列数字之和 + carry
resultDigit = total % 10
carry       = floor(total / 10)
```

每列生成一条 `MultiplicationAdditionStep`，记录 `columnFromRight`、各部分积在这一列的 `addendDigits`、进位、`total`、结果数字和下一列进位。这里的列号是算术位值，不是棋盘坐标。

当最高位相加产生进位时，该进位会在下一列成为最终积的最高位数字；它同时会作为教学标记显示在求和横线上。

## 6. 零与特殊情况

- 被乘数为 `0` 时，所有部分积为 `0`，最终积为 `0`。
- 乘数为 `0` 时，规范化后只有一个个位部分积 `0`，最终积为 `0`。
- 乘数中间的 `0` 仍须生成值为 `"0"` 的部分积，并保留它对应的 `shift`；排版层据此保留正确位置，不能跳过。
- 乘数末尾的 `0` 不做快捷裁剪；它自然生成个位（或低位）的零部分积，后续部分积按 `shift` 错位。
- 最终积不写前导 `0`；例如计算中间得到 `0123` 时，输出为 `"123"`。

## 7. 计算层输出契约

`MultiplicationComputation` 是计算层与乘法排版层之间唯一的中间过程，不能含行号、列号、像素、DOM 或 SVG 数据：

```ts
{
  multiplicandDigits: string,
  multiplierDigits: string,
  operandsSwapped: boolean,
  productDigits: string,
  partialProducts: MultiplicationPartialProduct[],
  additionSteps: MultiplicationAdditionStep[],
}
```

排版层可以读取 `shift`、进位和最终积安排竖式，但不得重新执行逐位乘法或按列求和。渲染坐标、横线和样式 token 由 [`乘法竖式排版规则.md`](./乘法竖式排版规则.md) 定义。

## 8. 验证清单

| 输入（被乘数 × 乘数） | 期望部分积 / 积 |
| --- | --- |
| `145 × 12` | `290 (shift 0)`、`145 (shift 1)`，积 `1740` |
| `123 × 101` | `123 (shift 0)`、`0 (shift 1)`、`123 (shift 2)`，积 `12423` |
| `145 × 2` | `290`，积 `290` |
| `145 × 0` | `0`，积 `0` |
| `0 × 12` | 交换为 `12 × 0`：一个零部分积，积 `0` |
| 超长数字串 × `1` | 积等于原数字串 |

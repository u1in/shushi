# 小学乘法竖式与通用棋盘排版规则

> 版本：V1.0  
> 适用范围：小学竖式项目中乘法器的竖式坐标、棋盘场景、DOM/CSS 与 SVG 对照渲染

整数逐位乘法和过程数据见 [`乘法计算规则.md`](./乘法计算规则.md)。本文件只定义 `MultiplicationComputation` 如何编排为通用棋盘，不在渲染器中实现乘法规则。

## 1. 分层与职责

```text
MultiplicationComputation → createMultiplicationBoardScene → BoardScene → DOM / SVG renderer
```

- `src/calculators/multiplication.ts` 输出字符串数字、逐位进位、部分积、十进制位移和按列求和过程。
- `src/layouts/multiplication-layout.ts` 读取这些过程数据，处理右对齐、部分积错位、可见进位和两条横线。
- `BoardScene` 仍是完全通用的可变轨道场景，不理解被乘数、部分积或进位。
- `src/renderers/dom-board-renderer.ts` 与 `src/renderers/svg-board-renderer.ts` 只消费 `BoardScene`；它们不得判断乘数位或重新计算进位。

## 2. 棋盘轨道与对齐

普通数字列宽为 `1u`，其中 `u = cellWidth`。最左另设 `0.72u` 的运算符列，乘号 `×` 位于该列的乘数行。数字区域的列数取被乘数、乘数、部分积（含 `shift`）和最终积所需宽度的最大值。

- 被乘数、乘数和最终积的最后一位均与数字区域最右列对齐。
- 一个部分积的最后一位对齐到 `数字区域最右列 - shift`；因此个位部分积右对齐，十位部分积左移一格，百位部分积左移两格。
- 数字区域列数先由布局层完整计算。渲染器不能为对齐目的测量 DOM 或修改轨道。

## 3. 行结构

```text
Row 0：被乘数
Row 1：× 乘数；底边为输入横线
可选短 Row：本部分积的进位标记；首个短行的底边为输入横线
Row：部分积（乘数有多位时，每一位都保留一行）
可选短 Row：部分积相加时的进位标记；底边为求和横线
最后 Row：最终积
```

- 只有一个乘数位时，唯一的部分积就是最终积，不重复绘制一行，也没有求和横线。
- 乘数有多位时，所有部分积（包括值为 `0` 的部分积）依 `shift` 绘制；最后一条部分积下方绘制求和横线，下一行绘制最终积。
- 一条部分积中只要任何 `digitSteps.carryOut > 0`，就在对应部分积上方增加一个 `0.36h` 的短进位行。首个短进位行位于乘数行和首个部分积之间，输入横线绘制在该短行的底边；因此进位在横线上方且独立占用轨道。这里不再插入额外留白轨道，横线会紧贴进位轨道的底边。
- 后续部分积若有进位，也在对应部分积上方增加短进位行；这不会改变输入横线的位置。
- 多位乘数的部分积相加若任一 `additionSteps.carryOut > 0`，就在最终部分积和求和横线之间加入一条 `0.36h` 的短加法进位行。进位位于它将参与下一高位求和的位置，求和横线绘制在该短行的底边；没有加法进位时，求和横线仍位于最终部分积的底边。
- `showCarrySteps` 关闭时，逐位乘法进位和加法进位的文本单元格、短进位行都会一起省略；计算层的 `digitSteps` 与 `additionSteps` 不受影响。
- 进位文本使用 `fontSizeRatio: 0.42`，即按 `BoardScene.fontSize` 缩小为教学标记。该属性是通用文本单元格能力，DOM/CSS 与 SVG 渲染器以相同方式处理，不包含任何乘法专属判断。
- 进位显示在它将参与下一高位计算的位置；最高位的进位显示在该部分积新增最高位的位置。
- 输入横线覆盖运算符列和全部数字区域；求和横线覆盖数字区域。两条横线都由跨列空 `BoardCell` 的 `bottom` 边绘制，而不是由渲染器创建独立线段。
- `uniformMultiplicationBars` 开启时，求和横线扩展到运算符列，使它与输入横线同起点、同终点、同宽；关闭时保留默认教学排版，即输入横线含运算符列、求和横线只覆盖数字区域。

## 4. `BoardCell` 与语义样式

文本均使用 `BoardCell.content.kind = "text"`；横线使用 `BoardCell.edges.bottom = true`。乘法专用 token 由布局层填写：

| token | 用途 |
| --- | --- |
| `multiplication.multiplicand` | 被乘数 |
| `multiplication.multiplier` | 乘数 |
| `multiplication.operator` | 乘号 `×` |
| `multiplication.carry` | 逐位乘法短进位行中的小号、底部对齐进位提示 |
| `multiplication.addition-carry` | 部分积相加时的小号、底部对齐进位提示 |
| `multiplication.partial-product` | 多位乘数产生的部分积 |
| `multiplication.product` | 最终积；一位乘数时也承载唯一部分积 |
| `multiplication.input-bar` | 乘数行下的输入横线 |
| `multiplication.sum-bar` | 多位乘数的部分积求和横线 |

`src/styles/main.css` 只按上述 token 着色；DOM/CSS 与 SVG 均复用相同 token。文本的水平/垂直对齐未在单元格覆盖时，继承 `BoardScene.textHorizontalAlign` 与 `BoardScene.textVerticalAlign`。`showGuideGrid` 覆盖所有已解析轨道，用于检查错位，不属于乘法计算过程。

## 5. 示例：145 × 12

计算层导出：

```text
部分积 290，shift 0（5 × 2 时向十位进 1）
部分积 145，shift 1
最终积 1740
```

布局得到的阅读结构为：

```text
      145
×      12
─────────
        1       ← 第一部分积的进位行
      290
     145
─────────
     1740
```

进位、部分积和最终积的精确列均由 `shift` 和 `digitSteps` 推导；示意中的空格不表示像素坐标。

## 6. 同步与验证

修改列宽、行结构、错位、进位、横线、token、`BoardScene` 或任一渲染器时，必须同步更新本文件；同时检查 [`竖式项目通用架构.md`](./竖式项目通用架构.md) 是否需要反映共享契约变化。

完成后至少运行：

```bash
source ~/.zshrc
npm run typecheck
npm run test
npm run build
```

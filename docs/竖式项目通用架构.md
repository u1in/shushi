# 小学竖式项目：通用架构与扩展规则

> 版本：V1.3
> 适用范围：项目级的计算器、棋盘场景、渲染器与规则文档约定

## 1. 项目目标

本项目用于展示小学四则运算的计算过程与竖式。当前已实现除法器和乘法器；加法、减法及后续运算器应复用通用棋盘和渲染器，但各自保留独立的计算规则与版式规则。

## 2. 统一分层

```text
<Operation>Computation
        ↓
create<Operation>BoardScene
        ↓
BoardScene
        ↓
SVG renderer / DOM + CSS renderer
```

- **计算层**：验证输入，执行运算，输出可检查的过程数据与语义 token。禁止输出像素、DOM、CSS 或渲染器专属数据。
- **运算版式层**：将某一运算的过程数据转换为 `BoardScene`。商、进位、借位、部分被减数、部分减数、部分积等都属于此层的运算规则。
- **通用棋盘层**：用可变尺寸轨道和 `BoardCell` 描述场景，不理解具体运算。
- **渲染层**：SVG 与 DOM/CSS 只根据 `BoardScene` 画出轨道、文本、边框、圆角与调试网格。

## 3. `BoardScene` 契约

`BoardScene` 包含：

- `columns` / `rows`：以单位宽高定义的可变轨道；尺寸允许为 `0`，零尺寸轨道不占宽高，只提供一条对齐线；
- `padding`、`unitWidth`、`unitHeight`、`fontSize`：场景尺寸与默认字体配置；
- `cells`：可带文本、圆角、边框及跨行/跨列的单元格；文本可选 `fontSizeRatio`，以场景默认字号为基准缩放局部教学标记；
- `textHorizontalAlign` / `textVerticalAlign`：场景级全局文本对齐；
- `showGuideGrid`：全轨道辅助网格；
- `ariaLabel`：场景级无障碍说明。

文本单元格可以在 `content.horizontalAlign` / `content.verticalAlign` 提供局部覆盖值。解析优先级为：**单元格覆盖 → 场景全局配置 → 渲染器基础样式**。

### 3.1 零尺寸轨道与内容侵入

- `BoardTrack.size` 必须是非负有限数；`0` 是合法值。零尺寸轨道不增加棋盘宽高，但保留轨道索引和边界，供横线、小数点、进位等结构图元使用。
- 文本单元格按“锚点 + 自然尺寸盒”放置：文本盒保持内容自然宽度，不换行、不裁剪。对齐值决定盒子哪一侧贴在单元格边界上；在 0 宽列 / 0 高行里边界退化为一条线，于是 `left` / `top` 向右侧 / 下方延伸，`center` 骑线居中，`right` / `bottom` 向左侧 / 上方延伸。
- 因此 0 尺寸轨道上的内容可以侵入相邻行列。这是有意的布局技巧，不是渲染错误。排版层必须给结构图元显式设置 `horizontalAlign` / `verticalAlign`，不要依赖场景级全局对齐，否则页面上的对齐控件会把小数点或进位推离预期位置。
- 内容墨迹必须留在棋盘矩形内：SVG 的 `viewBox` 和 DOM 的滚动 / 裁切祖先都会裁掉棋盘外的内容。需要向棋盘外延伸时，由排版层通过 `padding` 预留空间。
- 绘制顺序：边框层始终在文本层之下；同一层内按 `cells` 数组顺序绘制。内容重叠时，后出现的单元格压住先出现的单元格。
- 排版层可以为结构图元**预创建** 0 尺寸轨道和空单元格（例如乘法的进位列 / 进位行），即使当前没有内容。它们不改变棋盘尺寸，但能让轨道索引与结构保持稳定；渲染器不需要知道这些轨道是否为空。

版式适配器共同接收 `BoardRenderSettings`（方格宽度、行高、字号比例、辅助网格和默认文本对齐）。运算专属设置不得反向进入其他运算的计算层；例如除法的厂字弯、减法线和零商步骤设置属于 `RenderSettings`，乘法的横线等宽与进位显示设置属于 `MultiplicationRenderSettings`。

## 4. 源码目录

| 目录 | 职责 |
| --- | --- |
| `src/app/` | 页面入口、交互状态、数据流面板及命名图谱入口 |
| `src/calculators/` | 各运算的输入校验、算法和过程结果 |
| `src/layouts/` | 各运算的过程结果到 `BoardScene` 的排版适配 |
| `src/scene/` | 共享的场景类型、轨道解析和几何工具 |
| `src/renderers/` | 消费 `BoardScene` 的 SVG 与 DOM/CSS 渲染器 |
| `src/styles/` | 页面和渲染器的共享主题 |

主页中每一种运算展示都使用同级的 `<div class="operation-demo operation-demo--<operation>">` 容器。容器内放置该运算的专属链接、输入控件和结果区；新增运算器应复制这一结构，而不是把不同运算的控件直接混入既有容器。每个结果区的 `CALCULATION` 面板提供独立的“查看数据”是/否单选组，默认选择“否”：它只切换同级 `.data-flow-panel` 的可见性及结果网格宽度，不得改变计算结果、`BoardScene` 或渲染器输入。渲染模式的“两者”选项会并排显示 SVG 与 DOM/CSS，并强制将“查看数据”切换为“否”且禁用这组单选项；切回单一渲染模式后，单选项恢复可用。

## 5. 新运算器接入清单

每新增一种运算器，至少完成：

1. 新建计算模块，例如 `src/calculators/addition.ts`，并定义 `<Operation>Computation`；
2. 新建该运算规则文档，例如 `docs/加法计算规则.md`；
3. 新建版式编排器，例如 `src/layouts/addition-layout.ts`；
4. 新建或扩展中文命名的专项排版文档，例如 `docs/加法竖式排版规则.md`；
5. 为计算规则、布局映射、异常输入和关键边界条件添加测试；
6. 仅通过 `BoardScene` 连接既有 SVG / DOM 渲染器；
7. 如提供图谱，记录可见物件、线框边界与 JSON 字段说明。

不要为了“统一”而把不同运算的算法、过程对象或行列规则压缩为一个除法风格的数据结构。
